# Form 1040 line 1b — how the app does it

IRS rules: `C:\us-tax\new_lines\1b.md`. Flowchart: `C:\us-tax\new_flowcharts\1b.md`.
Paths are relative to `C:\us-tax`. `TRCS` = `us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`.

---

## 1. Status

Line 1b is computed. On the Employment form each person answers four gates (wages Yes → household work Yes → payer
controlled the work Yes → "received a W-2 for this household work" No) and lists household employers with their
wages; the compute sums the wages of every employer not marked "treated as a contractor", adds the spouse's total
unless the return is married filing separately, rounds, and stores `form1040.income.householdEmployeeWages`. The
$2,800 figure is shown only as a hint, which matches the IRS (it is not a test for the line). Because the input is a
per-person personal form, not a statement, the D-1a-1 problem (a dependent's statement counted on the parent's
return) does **not** repeat here.

**7 differences from the IRS rules** (D-1b-1 … D-1b-7). The most serious: household wages that the employer paid on
a 1099 are forced onto Form 8919 / line 1g with 7.65% social security and Medicare tax even when the $2,800 test
says none is owed (D-1b-2); household-work pay that fails the control test is dropped with only an advisory and a
stale "not supported" UI message (D-1b-4); and line 1b is left out of Form 2441 earned income (D-1b-5) and of IRA
compensation (D-1b-6).

## 4. How it is computed

Methods:

- Assembly: `buildIncome`, line 1b block `TRCS:18308-18316`, rounding `TRCS:18436`, line 1z `TRCS:18487-18488`,
  output `TRCS:18581-18583`.
- `sumHouseholdEmployeeWages` `TRCS:42334-42344` (taxpayer + spouse, MFS guard).
- `householdEmployeeAmount` `TRCS:42346-42382` (gates and per-employer loop).
- Return scoping: MFS legs drop the other spouse's forms and rename the spouse leg's `-spouse` forms to `-taxpayer`
  (`us-tax-be/src/main/java/com/ustax/microservices/multireturn/MfsFormScoper.java:314-392`); a dependent's own return
  is built from a synthetic form map with no Employment form (`multireturn/DependentOwnFormScoper.java:150-200`).

Steps, mirroring `new_lines/1b.md` section 6:

1. **Household work as an employee?** Per person, `householdEmployeeAmount` returns null unless
   `hasEmploymentIncome` = true (`TRCS:42355-42357`), `householdWork` = true and `householdEmployeeUnderControlTest`
   = true (`TRCS:42358-42366`). Control test = No raises the **non-blocking** advisory
   `HOUSEHOLD_WORK_SELF_EMPLOYMENT_<PERSON>` telling the user to add a Schedule C business
   (`TRCS:14090-14114`); nothing checks that a business was added, and the Employment form's own warning says
   self-employment "is not supported" (D-1b-4).
2. **W-2 check.** One answer per person: `householdReceivedW2` must be exactly false (`TRCS:42367-42369`). True →
   the whole list is ignored (and the UI clears it on save), so a person with one household employer that gave a W-2
   and another that did not loses the second one if they answer Yes (D-1b-3). There is no per-employer W-2 question.
3. **Add the wages.** For each row of `householdEmployers`: a row with `employerTreatedAsContractor` = true is
   skipped (`TRCS:42377-42380`); otherwise `wages` is added (blank = nothing) (`TRCS:42381-42382`). The skipped
   wages are expected on Form 8919: the blocking, non-overrideable flag
   `MISMATCH_CONTRACTOR_HOUSEHOLD_NEEDS_FORM_8919_<PERSON>` fires until a Form 8919 firm row with a matching name
   exists (`TRCS:14242-14290`), and Form 8919 then charges 6.2% + 1.45% on them with no $2,800 test or family
   exclusion (`computeForm8919ForPerson`, `TRCS:40381-40470`) (D-1b-2). Amounts keep cents.
4. **Spouse.** `sumHouseholdEmployeeWages` adds the spouse's amount unless `filing-status.filingStatus` is "Married
   filing separately" (`TRCS:18314-18316`, `TRCS:42339-42342`). On an MFS leg the spouse's form has already become
   the filer's `-taxpayer` form, so each leg shows its own person. On a community-property MFS return household wages
   are not split (`CommunityProperty` splits W-2 box 1 only) (D-1b-7).
5. **Round.** `roundMoney` (half-up, whole dollars) on the summed total (`TRCS:18436`).
6. **Output.** Stored on `Income.householdEmployeeWages` only when not null (`TRCS:18581-18583`); there is no
   "0 when answered Yes" state as there is for line 1a.

A dependent's own return never has a line 1b: the dependent tab has no Employment form, and
`DependentOwnFormScoper` builds the dependent's form map without one (D-1b-1).

## 5. Flags and advisories

| Code | Blocks? | When | Tells the user | Where |
|---|---|---|---|---|
| `HOUSEHOLD_WORK_SELF_EMPLOYMENT_TAXPAYER` / `_SPOUSE` | No | Wages Yes, household work Yes, control test No | The worker is self-employed; report the income on a business (Schedule C) entry | `TRCS:14090-14114` (calls `TRCS:3522-3523`); UI link `us-tax-ui/src/app/data/flag-form-links.ts:389-390` |
| `MISMATCH_CONTRACTOR_HOUSEHOLD_NEEDS_FORM_8919_TAXPAYER` / `_SPOUSE` | Yes (non-overrideable) | A household row marked contractor with wages > 0 has no Form 8919 firm row of a matching name | Add the Form 8919 firm row, or clear the contractor answer | `TRCS:14242-14300` (calls `TRCS:3536-3537`); `NonOverrideableFlags.java:39-40` |
| `WITHHOLDING_ON_CONTRACTOR_HOUSEHOLD_FIRM_NEEDS_1099_STATEMENT_TAXPAYER` / `_SPOUSE` | Yes (non-overrideable) | A contractor-marked row with "federal tax withheld" = Yes has no 1099-MISC / 1099-NEC whose payer name matches | Add the 1099 so its withholding reaches line 25b, or clear the answer | `TRCS:14140-14197` (calls `TRCS:3528-3529`); `NonOverrideableFlags.java:45-46` |
| `MISSING_W2_EMPLOYMENT_INCOME_TAXPAYER` / `_SPOUSE` | Yes | Fires only when household work = **No**; answering Yes turns it off for that person even if they also had ordinary W-2 jobs | A W-2 is required | `TRCS:13771-13795` |

The UI also shows, per non-contractor row with "federal tax withheld" = Yes, a warning that the employer had to
issue a W-2 and pointing to Form 4852; the backend does not read that answer for line 1b.

## 8. Compared with the IRS rules

| # | IRS rule (source) | What the app does | Result |
|---|---|---|---|
| 1 | Total of wages as a household employee not reported on a W-2 (`i1040gi_ty2025.pdf p. 24`) | Sum of `householdEmployers[].wages` after the gates (`TRCS:42346-42382`) | Match |
| 2 | The $2,800 figure explains why a W-2 may be missing; it is not a condition (`i1040gi_ty2025.pdf p. 24`) | Shown as a hint only; never compared with the total | Match |
| 3 | Household employee = payer controls what and how (`i1040sh.pdf p. 2`) | Control-test question; Yes required | Match |
| 4 | Household wages on a W-2 go on line 1a | W-2 = Yes → excluded from line 1b | Match (but see D-1b-3) |
| 5 | Joint return: both spouses; separate returns: each their own | Spouse added unless MFS; MFS legs use each person's form (`TRCS:42339-42342`, `MfsFormScoper.java:314-392`) | Match |
| 6 | Rounding: add with cents, round the total (`i1040gi_ty2025.pdf p. 23`) | `roundMoney` on the sum (`TRCS:18436`) | Match |
| 7 | A child's earnings are the child's income (`p17.pdf p. 10`); a dependent with household wages reports them on the dependent's own line 1b | No Employment form on a dependent tab; `DependentOwnFormScoper.java:150-200` builds the dependent's return without one; no flag. The parent's return is correctly unaffected (no D-1a-1 repeat), but the dependent's own line 1b, line 1z, earned-income standard deduction and filing-requirement figures omit the wages | **Not supported D-1b-1** (silent) |
| 8 | Household wages not on a W-2 → line 1b (`i1040gi_ty2025.pdf p. 24`). Social security / Medicare apply only when one employer pays $2,800 or more in cash wages, excluding the employer's spouse, child under 21, parent and under-18 workers (`i1040sh.pdf p. 4–5`); Form 8919 is for an employee whose employer did not withhold those taxes and who has reason code A, C, G or H (`f8919.pdf p. 1`) | A household row marked "paid as a contractor / 1099" is removed from line 1b (`TRCS:42377-42380`) and a non-overrideable blocker forces a Form 8919 row (`TRCS:14242-14300`); Form 8919 then adds the wages to line 1g and charges 7.65% (`TRCS:40381-40470`) with no $2,800 or family test. Example: $1,500 from one family on a 1099-NEC → line 1g $1,500 (line 1z unchanged) and $115 of Schedule 2 line 6 tax that is not owed, plus a reason code the worker may not have | **Deviation D-1b-2** |
| 9 | Each household employer's wages not on a W-2 count (`i1040gi_ty2025.pdf p. 24`) | One "Did you receive a Form W-2 for this household work?" answer per person; Yes discards every row (UI clears the list, backend returns null, `TRCS:42367-42369`). Help text: "If you received a W-2, the wages belong on line 1a instead of line 1b." A person with one W-2 household job and one without who answers Yes loses the second job's wages | **Deviation D-1b-3** (silent, needs that answer) |
| 10 | Self-employed household worker → Schedule C (`i1040sh.pdf p. 2`; `f8919.pdf p. 2`) | Control test No → wages left out of line 1b with a non-blocking advisory to add a Schedule C business (`TRCS:14090-14114`); the Employment form says "Self-employment is not supported by this application — this income cannot be entered here" (`form-employment-taxpayer.component.ts:205-208`, help `:1176-1179`; spouse `:207-209`), stale since self-employment came into scope on 2026-07-20. Nothing checks a business was added | **Not supported D-1b-4** (income dropped if the advisory is ignored; the UI text tells the user to ignore it) |
| 11 | Form 2441 earned income starts from line 1z (`i2441.pdf p. 4`) | `computeDependentCareBenefits` builds each person's earned income from W-2 box 1 by SSN, tips, line 1g, line 1h and a typed "additional earned income"; line 1b is not added (`TRCS:38961-39011`). A filer whose only job is household work without a W-2 has earned income 0 → no dependent-care credit, and the §129 exclusion limit is understated | **Deviation D-1b-5** (silent unless the user types the amount as additional earned income) |
| 12 | IRA compensation includes wages for personal services (`p590a.pdf p. 6`) | `computeIraCompensation` reads W-2 box 1 (+ combat pay, alimony, SE earnings) only (`TRCS:41140-41148`, `:4722-4741`); a contribution backed by household wages raises the blocking (overrideable) `IRA_DEDUCTION_EXCEEDS_COMPENSATION_<PERSON>` | **Deviation D-1b-6** (false blocker) |
| 13 | Community property, separate returns: community income split under state law (`i1040gi_ty2025.pdf p. 23`) | `CommunityProperty` splits W-2 box 1, interest, dividends, business and other items but not household wages; each MFS return keeps its own line 1b in full. Registered domestic partners are not modelled (as D-1a-8) | **Not supported D-1b-7** (silent) |
| 14 | Household wages count as earned income for EIC, Schedule 8812, dependent standard deduction (`i1040gi_ty2025.pdf p. 35, p. 42`) | Included (`TRCS:51250-51259`, `:56332`) | Match |
| 15 | Income tax withheld by a household employer means a W-2 was required (`i1040sh.pdf p. 2–3`) | UI warning per row pointing to Form 4852; no compute effect (the withholding needs Form 4852 to reach line 25a) | Match (guidance) |

## 9. Limits and out of scope

- **Schedule H** (the household *employer's* taxes, Schedule 2 line 9) is a separate form in the app (B62) and is not
  part of line 1b.
- **Noncash pay**: the single "Wages" field per employer takes whatever the user enters; there is no separate noncash
  field (the IRS has no separate line either).
- **Employer name** is used only for the name matching in the two contractor blockers.
- Line 1b stays null (never 0) when no household wages are computed — the field is omitted from the JSON.
