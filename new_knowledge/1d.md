# Form 1040 line 1d — how the app does it

IRS rules: `C:\us-tax\new_lines\1d.md`. Flowchart: `C:\us-tax\new_flowcharts\1d.md`.
Paths are relative to `C:\us-tax`. `TRCS` = `us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`.
`UI-T` = `us-tax-ui/src/app/forms/form-medicaid-waiver-taxpayer.component.ts` (the spouse copy,
`form-medicaid-waiver-spouse.component.ts`, is the same form).

---

## 1. Status

Line 1d is computed from the per-person "Medicaid waiver payments" form (taxpayer and spouse), not from statements.
For each payer row the user splits the payment into a qualified (Notice 2014-7) amount, the part of it inside W-2 box
1, and a taxable amount not in box 1. Line 1d = taxable amounts + the §131(c) over-limit share + (with the per-person
election) the qualified amounts not in box 1. Schedule 1 line 8s backs out the qualified amount inside W-2 box 1
(always) plus the elected amount. Care outside the caregiver's home is taxed (row-level answer; a form-level "No"
blocks). The EIC and Schedule 8812 apply the election per credit. A home-care business blocks the return.

**7 differences from the IRS rules** (D-1d-1 … D-1d-7). The most serious: the form pre-fills a row from **every** W-2
in the household that has box 12 code II — the spouse's and the dependents' included — into each person's form
(D-1d-1, same root cause as D-1a-1); the §131(c) over-limit share of a payment inside W-2 box 1 is taxed twice
(D-1d-2); and Form 1099-MISC / 1099-NEC payments are left off line 1d / line 8s when the person does not elect
(D-1d-3). D-1d-1 and D-1d-2 change taxable income or credits with no flag.

## 4. How it is computed

Methods:

- Load: `TRCS:2697-2698` (`medicaid-waiver-payments-taxpayer` / `-spouse`); MFS test `TRCS:3548-3549`; call
  `TRCS:3562-3571`.
- Household total: `computeMedicaidWaiverPayments` `TRCS:38371-38403`.
- Per person: `computeMedicaidForPerson` `TRCS:40556-40909`.
- Assembly: `buildIncome` rounding `TRCS:18438`, output `TRCS:18587-18589`; line 8s `TRCS:32493`, `:32710`.
- Scoping: on an MFS leg the generic `-spouse` → `-taxpayer` form swap of `MfsFormScoper` gives each spouse their own
  form (pinned by `mfs-spouse-medicaid-waiver.spec.ts`); a dependent's own return drops all household forms
  (`multireturn/DependentOwnFormScoper.java`, class comment), so no Medicaid form exists there (D-1d-7).

Steps, mirroring `new_lines/1d.md` section 6 (per person; the spouse is skipped on MFS, `TRCS:38391-38393`):

0. **Gate.** Nothing is computed unless "received" is Yes and the form exists (`TRCS:40562-40568`).
1. **Home-care business.** Yes → blocking, non-overrideable `MEDICAID_WAIVER_SCHEDULE_C_<PERSON>`; the person's
   result is empty (`TRCS:40578-40597`). Fires even with no rows. The message says "this application does not
   produce Schedule C", but Schedule C is computed by the app since 2026-07-20 (D-1d-4).
2. **Qualified vs not.** Per row (`TRCS:40611-40730`):
   - The user's split is trusted: `qualifiedNotice2014_7Amount`, `qualifiedAmountIncludedInW2Box1`,
     `taxablePaymentsNotInW2Box1`.
   - Row answer "lives in your home" = No (and no exception): the qualified part **not** in box 1 is added to the
     taxable amount, the box 1 part stays on line 1a with no line 8s back-out, and the advisory
     `MEDICAID_WAIVER_CARE_NOT_IN_PROVIDER_HOME_<PERSON>` is raised (`TRCS:40711-40722`). Matches
     `notice-2014-7.pdf p. 6`.
   - Row answer blank: the row counts as qualified; the form-level "lives with" answer then gates it (step 2b).
   - 2b. Form-level answer No, no exception, and an amount actually excluded (box 1 part always, non-box-1 part only
     when elected) → blocking (overrideable) `MEDICAID_WAIVER_NOTICE_2014_7_HOME_SHARING_VIOLATION_<PERSON>`
     (`TRCS:40758-40803`).
3. **Head-count limit.** If under-19 count > 10 or 19-plus count > 5 (`ReferenceData.java:210-211`), the fraction
   `(min(u,10) + min(a,5)) / (u + a)` of the qualified total stays excludable; the rest (`capExcessTaxable`) goes to
   line 1d (`TRCS:40812-40834`). The box-1 and not-in-box-1 qualified parts are both scaled by the fraction
   (`TRCS:40838-40843`). The over-limit share of a payment **inside box 1** is therefore taxed twice — once on line 1a
   (not backed out) and again on line 1d (D-1d-2). The limit is also applied per person, not per home (row 13 of §8).
   Pro-rata is the code's own convention; the IRS documents give no allocation method.
4. **Locate each part.** For a row with source type W-2 the matching W-2 is looked up by the filer's SSN and the
   payer's EIN or name (`TRCS:40636-40654`, `findMatchingW2Entry` `TRCS:52425-52457`); a blank "included in box 1"
   becomes 0 if no W-2 matches or its box 1 is 0, and is blocking otherwise. Nothing checks that the typed box-1
   amount is really in a W-2 on file or is no more than its box 1 (D-1d-6).
5. **Line 1d (always):** `taxableNonW2 + capExcessTaxable` (`TRCS:40845`). A 1099-MISC / 1099-NEC row counts only
   through "Taxable payments not in W-2 box 1" (the picker pre-fills it there); when the user moves a 1099 amount to
   "Qualified", it leaves line 1d unless elected (D-1d-3).
6. **Line 1d (election):** + the (scaled) qualified amount not in box 1 (`TRCS:40846-40855`).
7. **Line 8s:** − (scaled qualified amount in box 1, always; + scaled qualified amount not in box 1 when elected)
   (`TRCS:40867-40890`).
8. **Joint return:** taxpayer + spouse (`TRCS:38394-38395`). On Single / HOH / QSS the spouse form is still added if
   one is on file — only MFS is guarded (D-1d-5).
9. **Round:** `roundMoney` half-up on the household total (`TRCS:18438`); line 8s rounded at `TRCS:32710`.
10. **Credits:** the per-person "not elected, in box 1" amount is subtracted from EIC earned income
    (`TRCS:51237-51240`) and Schedule 8812 line 18a (`TRCS:56482-56490`); line 1d is added to EIC earned income
    (`TRCS:51246-51248`). With the election on, the EIC is figured both with and without the elected amount and the
    larger kept (`TRCS:51443-51470`, advisory `MEDICAID_WAIVER_LEFT_OUT_OF_EIC_EARNED_INCOME`); with it off, an
    advisory says how much the ACTC would rise (`TRCS:55780-55802`). This matches EIC Step 5 line 2 and Schedule 8812
    line 4, which each ask separately.

## 9. Limits and out of scope

- **Schedule SE election.** `medicaidWaiverIncludeInSe` adds the person's whole line 1d amount (taxable 1099 / no-form
  payments **and** elected excluded payments) to Schedule SE line 2 (`TRCS:29210-29212`). The 2025 IRS books
  (`i1040sse.pdf`, `i1040gi_ty2025.pdf`) contain no such election; not verified.
- **Nondeductible IRA limit increase** for excluded difficulty-of-care payments (`p590a.pdf p. 16`) — no code
  reference found (no `difficulty` field outside this form); belongs to the IRA / Form 8606 documents.
- The split of each payment (qualified / box 1 / taxable) is the user's; the app does not derive it from W-2 box 1 and
  code II except for the UI pre-fill.
- `programName` and `careRecipientRelationship` are stored only.
