# Form 1040 line 1f — how the app does it

IRS rules: `C:\us-tax\new_lines\1f.md`. Flowchart: `C:\us-tax\new_flowcharts\1f.md`.
Paths are relative to `C:\us-tax`. `TRCS` = `us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`.

---

## 1. Status

Line 1f is computed from Form 8839 Part III. The app reads W-2 box 12 code T of the filer (and the spouse on a joint
return), asks on the "Adoption expenses" form how the benefits split across up to six children, applies the $17,280
per-child limit (less prior-year benefits, or a shared-adoption share), the special-needs rule, the MAGI phase-out,
the foreign-child prior-year rule and the more-than-2% S corporation bar, and puts line 31 (plus any S-corporation
disallowed amount) on line 1f. Line 1f may be negative. Married filing separately without the lived-apart answer puts
all code T on line 1f. Blocking flags cover code T with no adoption form, no child, an allocation that does not add up,
a foreign child not final, a missing finality answer and off-W-2 benefits for a non-special-needs child.

**10 differences from the IRS rules** (D-1f-1 … D-1f-10). The most serious: when MAGI is derived by the app (the only
path the UI offers) and it reaches the phase-out, line 1f is raised **after** line 1z, AGI and the tax were figured, so
the added taxable benefits never reach the tax (D-1f-1); and the line 25 MAGI formula adds line 23 on top of an AGI that
already holds line 1f, and drops the student-loan add-back, so the phase-out fraction is wrong whenever line 1f is not
zero (D-1f-2). Several input paths (prior-year benefits and foreign prior-year benefits when there is no 2025 code T;
the married-filing-separately household tests; per-child eligibility) are missing and produce a wrong amount silently.

Unlike line 1a (D-1a-1), line 1f **does** filter W-2s by person: a dependent's code T is not counted on the parent's
return (`TRCS:39280-39289`).

## 4. How it is computed

Methods:

- Load and merge: `TRCS:2830-2832` → `mergeAdoptionForms` `TRCS:38664-38710`.
- Phase 1 (before AGI): `computeAdoptionBenefits` `TRCS:39265-39929`, called at `TRCS:3601`.
- W-2 sums: `sumW2AdoptionBenefitsForSsns` `TRCS:41399-41440`, `sumW2AdoptionBenefits` `TRCS:41365-41392`,
  `computeSection1372DisallowedFromEligibleW2BoxT` `TRCS:41459-41523`, `resolveSharedAdoptionCap` `TRCS:41546`.
- Phase-out fraction: `computeAdoptionPhaseoutFraction` `TRCS:42496-42506` (4 decimals, half-up, capped at 1).
- Assembly: `buildIncome` `TRCS:18440` (round), `:18487` (into line 1z), `:18593-18594` (output).
- Phase 2 (after AGI and tax): `applyAdoptionCredit` `TRCS:44154-44333` (called at `TRCS:6906`) — the "G1" MAGI
  re-run of Part III.
- Constants: `us-tax-be/.../microservices/ReferenceData.java:214-216` ($17,280; $259,190; $40,000).

Steps, mirroring `new_lines/1f.md` section 6:

1. **Who may exclude / whose benefits.**
   - W-2 filter: code T of W-2s whose `employeeSSN` equals the filer's SSN, plus the spouse's SSN unless the return is
     MFS (`TRCS:39280-39289`). A dependent's W-2 is therefore left out (correct). If neither SSN is known, all W-2s count
     (`TRCS:39288`). A W-2 with no box a is skipped when an SSN is known (`TRCS:41409`).
   - Joint return: the two adoption forms are merged; the spouse's children are **appended** after the taxpayer's and
     their per-child amounts re-indexed; the §1372 per-W-2 marks and the manual MAGI are taken from the **taxpayer's
     form only** (`TRCS:38668-38709`). The same merge runs on a primary MFS return (both forms are kept there,
     `us-tax-be/.../multireturn/MfsFormScoper.java:772-790`); on an MFS leg the scoper keeps only the leg's own form
     (`MfsFormScoper.java:619-624`). (D-1f-6)
   - No code T and no adoption inputs → line 1f stays null (`TRCS:39379-39382`). Code T but no adoption inputs →
     blocking `ADOPTION_BENEFITS_FORM_REQUIRED` (`TRCS:39362-39369`).
   - MFS: if `filingStatus = Married filing separately` and `mfsOrHohLivedApartOrLegallySeparated` is not true, the
     whole (filtered) code T total is line 1f, with a non-blocking advisory, and no Form 8839 is produced
     (`TRCS:39387-39409`). With the answer Yes, Part III runs. The child-in-home and over-half-cost tests are not asked
     (D-1f-5).
   - More-than-2% S corporation owner: the code T of W-2s marked on the form is taken out of the Part III base and added
     to line 1f in full, with an advisory (`TRCS:39423-39446`; `TRCS:39892-39895`). On a joint return a reminder about
     stock attributed from family members fires when the answer is No (`TRCS:39457-39469`).
   - At least one child is required when there are benefits or inputs (blocking `ADOPTION_BENEFITS_CHILD_REQUIRED`,
     `TRCS:39484-39492`).
   - Eligible-child test (under 18 or disabled; not the spouse's child): **not applied**; `bornBefore2008AndDisabled`
     and `childYearOfBirth` are only copied to the output (`TRCS:42312-42332`) (D-1f-8).
2. **Which benefits are this year's.** Per child (`TRCS:39570-39610`): a foreign child with "final" = No blocks with
   `ADOPTION_BENEFITS_FOREIGN_CHILD_NOT_FINAL` and the child is skipped (D-1f-3). A special-needs child with no finality
   answer blocks with `ADOPTION_BENEFITS_FINALIZATION_REQUIRED`. Domestic children, final or not, proceed (correct).
3. **Per child, lines 19–24** (`TRCS:39709-39749`), only when Part III is allowed — 2025 code T present, or a
   special-needs child final in 2025, or a foreign final child with a deferred prior-year amount (`TRCS:39508-39526`).
   - Line 19 = $17,280, or the shared-adoption share (`TRCS:39616`). The same share is used for Part II line 2.
   - Line 20 = `child{n}PriorYearBenefits`; line 21 = max(0, line 19 − line 20).
   - Line 22 = `child{n}Benefits2025`. If every per-child allocation is empty, the code T total is split evenly, the last
     child taking the remainder (`TRCS:39535-39559`).
   - Line 24 = line 21 when special needs AND final AND the finality year is 2025 or blank; otherwise
     min(line 21, line 22 + deferred foreign prior-year amount) — the deferred amount only for a foreign, final,
     non-special-needs child (`TRCS:39722-39730`). Whether the employer has a QAAP is not asked (D-1f-9).
   - With no 2025 code T at all, a positive line 20 or line 22 for a child who is not special-needs-final (and not
     foreign-final with a deferred amount) blocks with `ADOPTION_BENEFITS_OFF_W2_NOT_SPECIAL_NEEDS_CHILD_{n}`
     (`TRCS:39685-39707`).
   - Line 23 = Σ line 22 (`TRCS:39840`). If |code T total − Σ line 22| > $1, blocking `ADOPTION_BENEFITS_ALLOCATION_MISMATCH`
     (`TRCS:39781-39794`).
4. **MAGI, line 25.**
   - Phase 1 uses `imports.magiForAdoptionBenefitsExclusion` only (`TRCS:39496`). The UI never sends it, so in normal use
     it is null, the phase-out fraction is taken as 0 (`TRCS:39497-39498`), and lines 25–27 stay blank in phase 1.
   - Phase 2 (`TRCS:44230-44331`), only when the manual MAGI is null: `autoMagi` = AGI (line 11b) + Puerto Rico
     exclusion + Form 2555 lines 45 and 50 (both spouses) + Form 4563 line 15 (`TRCS:44251`); line 25 =
     `autoMagi + line 23` (`TRCS:44303`). AGI already contains the phase-1 line 1f, and the student-loan deduction is
     not added back (D-1f-2).
   - When a manual MAGI is present it is used for both line 7 (credit) and line 25 (exclusion) unchanged; the helper
     `computeAdoptionAutoMagi` (`TRCS:42527-42553`, which does add back student-loan interest and line 30) is used only
     for the `ADOPTION_MAGI_MANUAL_VS_AUTO_MISMATCH` advisory (`TRCS:44207-44228`).
5. **Phase-out, lines 26–29.** Fraction = (MAGI − 259,190) / 40,000 to 4 decimals, half-up, floor 0, cap 1
   (`TRCS:42496-42506`). Line 28 = line 24 × fraction; line 29 = line 24 − line 28 (phase 1 `TRCS:39864-39871`;
   phase 2 `TRCS:44307-44314`, line 28 rounded to dollars).
6. **Lines 30–31.** Line 30 = Σ line 29; line 31 = line 23 − line 30, negative allowed; the Yes/No box is set
   (`TRCS:39873-39881`, phase 2 `TRCS:44315-44317`).
7. **Foreign child final in 2025 with prior-year benefits.** Modelled as an extra per-child input added to line 22 only
   inside the line 24 minimum (`TRCS:39722-39730`); lines 22/23 on the form show only 2025 benefits. Line 31 =
   2025 line 23 − line 30 can go negative even when the IRS worksheet (line 6) floors the taxable benefits at 0
   (D-1f-10). The input is offered in the UI only when the account has 2025 code T (D-1f-4).
8. **More than three children.** Up to six children computed on one Form 8839 model; seven or more → non-blocking
   advisories (`TRCS:39308-39324`, `:39471-39478`).
9. **Round and output.** Line 1f = round(line 31 + §1372 slice) (`TRCS:39889-39898`); null → 0 when adoption inputs
   exist but Part III did not run. `buildIncome` rounds it again and adds it to line 1z with no floor
   (`TRCS:18440`, `:18487-18494`). Phase 2 then **overwrites** `Income.adoptionBenefits` with the phased-out line 31
   (`TRCS:44326-44330`) — after line 1z, line 9, AGI and the tax were set, and nothing recomputes them (D-1f-1).

## 9. Limits and out of scope

- **Manual MAGI** exists in the data model but has no UI field; normal use always derives MAGI in phase 2.
- **Form 8839 Part II** (credit) is documented separately; Part III must come first, which the code respects
  (`TRCS:39634-39644` subtracts the child's code T from credit expenses).
- **Foreign adoption finality year** (Rev. Proc. 2005-31 / 2010-31 choice) is the user's answer; not modelled.
- **Several attempts for one child** must be combined by the user on one child row.
- **Qualified adoption expense** content (what the employer paid for) is trusted from code T.
