# Form 1040 line 1h — how the app does it

IRS rules: `C:\us-tax\new_lines\1h.md`. Flowchart: `C:\us-tax\new_flowcharts\1h.md`.
Paths are relative to `C:\us-tax`. `TRCS` = `us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`.

---

## 1. Status

Line 1h is computed by `computeOtherEarnedIncome`. It adds seven parts: disability pensions (Form 1099-R code 3,
answered "below minimum retirement age", less a PSO premium exclusion), excess elective deferrals (W-2 box 12, per
person, by age), corrective distributions (Form 1099-R code 8, not IRA), strike / lockout benefits (typed amount plus
1099-MISC box 3 tagged as strike pay), Form 2555 foreign wages the filer says are not reported elsewhere, Form 3903
excess government moving payments, and a minister's housing allowance above the excludable amount. Three blocking
flags force the user to say whose a 1099-R is and whether the pensioner was below the minimum retirement age. The
types are written next to the line (B85).

**15 differences from the IRS rules** (D-1h-1 … D-1h-15). The most serious, all silent: the 1099-MISC "strike
benefits" tag the line relies on cannot be set from the UI, so union strike pay on a 1099-MISC is left off unless
retyped — and the form tells the user not to retype it (D-1h-1); a spouse's typed strike pay is dropped on a joint
return (D-1h-2); a 2025 excess deferral returned in 2025 is counted twice (D-1h-5); an IRA disability distribution
answered "below retirement age" is counted on both line 1h and line 4b (D-1h-6); the excess-deferral limit leaves
designated Roth and SIMPLE deferrals out of the overall $23,500 test (D-1h-3, D-1h-4); and the EIC takes only the
disability part of line 1h as earned income (D-1h-10).

## 4. How it is computed

Methods:

- Form merge: `mergeOtherEarnedForms` `TRCS:38730-38756`, called `TRCS:2836-2838`.
- Main: `computeOtherEarnedIncome` `TRCS:39946-40263`, called `TRCS:3595-3598` (before Form 2441 / adoption /
  combat pay).
- Deferrals: `computeDeferralTotalsForSsn` `TRCS:41912-41920`, `computeExcessDeferralsForPerson`
  `TRCS:41922-41985`, codes `TRCS:128-130` (`D,E,F` / `S` / `G`), `sumW2Box12ByCodes` `TRCS:41568`.
- Strike: `sumStrikeBenefitsFrom1099Misc` `TRCS:42031-42048`. PSO: `computeLine1hPsoExclusion` `TRCS:42011-42029`.
- Foreign wages: `foreignEarnedWagesNotYetInIncome` `TRCS:39938-39944`. Moving: `form3903ExcessPayments`
  `TRCS:10392-10402` (W-2 code P added by `withForm3903CodeP`, `TRCS:3585-3588`). Clergy:
  `clergyExcessHousingAllowance` `TRCS:53555-53580`.
- Write-in: `line1hTypeText` `TRCS:55841-55864`. Record `OtherEarnedIncomeComputation` `TRCS:55866-55874`.
- Assembly: `buildIncome` rounds `TRCS:18442`, line 1z `TRCS:18487-18488`, output `TRCS:18599-18605`.
- Lines 5a/5b keep line-1h items out: `TRCS:21656-21666` (ids answered "below minimum age"), skip `TRCS:21991`,
  codes 8 / P skipped `TRCS:22002`.

Steps, mirroring `new_lines/1h.md` section 6:

0. **Merge and scope.** On a joint return the spouse tab's form is merged into the taxpayer's: the spouse's elections
   go to the `spouse` slots, the spouse's PSO answers to `psoExclusionSpouse`, the 1099-R selections are
   concatenated — but **the spouse's `strikeBenefits` is not copied** (D-1h-2) (`TRCS:38730-38756`). On MFS legs
   the scoper keeps only the filer's form (`multireturn/MfsFormScoper.java:625-632`). On MFS the spouse SSN, age and
   elections are nulled (`TRCS:39977-39981`, `:39999-40010`) and a 1099-R whose recipient TIN is the spouse's is
   skipped (`TRCS:40044-40046`). A dependent's own return has no Other earned income form at all (the scoper builds
   synthetic forms only, `multireturn/DependentOwnFormScoper.java:150-200`).
1. **Strike / lockout benefits.** `manualStrikeBenefitsAmount` (taxpayer form only on a joint return) plus box 3
   (`otherIncomeAmount`) of every 1099-MISC with `box3IsStrikeBenefits == true` (`TRCS:39986-39988`,
   `:42031-42048`). The 1099-MISC list is the whole account's, with no recipient-TIN filter on any filing status, but
   the tag cannot be set from the UI (D-1h-1, D-1h-13). Strike pay is not split by person.
2. **Excess elective deferrals.** For the taxpayer and (unless MFS) the spouse, W-2 box 12 amounts whose box a equals
   the person's SSN are summed in three separate pools (`TRCS:41912-41920`): codes D+E+F (`402g`), code S (SIMPLE),
   code G (457(b)). Roth codes AA, BB, EE and code H are not read (D-1h-4, D-1h-12). Limits
   (`TRCS:41932-41977`): 402g $23,500 (+$3,000 with the 403(b) 15-year answer); SIMPLE $16,500 or $17,600 with the
   §117 answer; 457(b) $23,500 or a flat $47,000 with the 3-year answer. Age at the end of 2025 from the date of
   birth: 50+ adds $7,500 / SIMPLE $3,500 (§117 $3,850) / 457(b) $7,500 (not with the 3-year answer); 60–63 adds
   $11,250 / $5,250 (§117 $5,775) / $11,250. Each pool's excess = total − limit if positive (`TRCS:41981-41993`); the
   three are added. The SIMPLE pool is never added to the 402g pool (D-1h-3). No check against code-8 1099-Rs
   (D-1h-5).
3. **Disability pensions.** For every 1099-R in the account with code 3 (`TRCS:40049-40079`): the owner is the
   spouse whose SSN equals the recipient TIN, else the saved `owner`, else `LINE1H_DISABILITY_OWNER_REQUIRED`
   (blocking). If the saved answer is missing, `LINE1H_DISABILITY_MIN_RETIREMENT_AGE_REQUIRED` (blocking). If the
   answer is Yes the amount is box 2a, or box 1 when 2a is blank. The IRA/SEP/SIMPLE box is **not** checked here,
   while the IRA path (lines 4a/4b) keeps every IRA entry (`TRCS:20938-20943`) (D-1h-6). Lines 5a/5b skip an entry
   answered Yes (`TRCS:21991`). PSO: per person, when eligible + elected + premiums > 0, the smaller of premiums and
   $3,000, capped at that person's disability total, is subtracted (`TRCS:40183-40193`, `:42011-42029`); the spouse's
   PSO is ignored on MFS. The $3,000 is not shared with line 5b's PSO (D-1h-9).
4. **Corrective distributions.** For every non-IRA 1099-R with code 8 or P and without code 3
   (`TRCS:40081-40146`): code 8 → box 2a is added (no fallback to box 1; a blank box 2a gives the advisory
   `LINE1H_CORRECTIVE_BOX2A_MISSING` and nothing is added); owner unresolved → `LINE1H_CORRECTIVE_OWNER_REQUIRED`
   (blocking). Code P alone → nothing is added, advisory `LINE1H_CODE_P_PRIOR_YEAR_INFO` (D-1h-7). Codes B+8 are
   treated like 8 (box 2a). Losses are not handled (D-1h-8).
5. **Form 3903.** For each spouse: when the move was answered as an active-duty move, moving costs > 0 and W-2 box 12
   code P > costs, add code P − costs (`TRCS:10392-10402`).
6. **Foreign wages without a W-2.** For each spouse (spouse not on MFS): Form 2555 type `wages` with "already in
   income?" answered No → `foreignWagesAmount` (`TRCS:40200-40202`). There is no other input for foreign-employer
   pay (D-1h-14).
7. **Clergy excess allowance.** Designated allowance − smallest of (allowance, amount used, fair rental value), when
   the person is clergy (`TRCS:53555-53580`); advisory `CLERGY_HOUSING_LIMIT_INPUTS_MISSING` when neither limit is
   entered. The "reasonable pay" ceiling is not applied (D-1h-15).
8. **Add and round.** `sumAmounts` of the seven parts with cents, `roundMoney` half-up (`TRCS:40215-40217`), rounded
   again in `buildIncome` (`TRCS:18442`). Line 1h is never negative. An all-null result stays null.
9. **Write-in.** Labels in order: "Disability pension wages" (or "… (PSO)"), "Excess elective deferrals",
   "Corrective distributions (current year)", "Strike/lockout benefits", "Excess moving reimbursement (Form 3903)",
   "Excess allowance", "Foreign earned wages" (`TRCS:40228-40256`); shortened and comma-joined, or "Various (see
   statement)" over 36 characters (`TRCS:55859-55864`). The PSO excluded amount is not written (D-1h-9); foreign
   wages are not labelled "FEC" (D-1h-14).
10. **Per-person earned parts** for Form 2441: disability (after PSO) + excess deferrals + foreign wages + moving
    excess + clergy excess; corrective distributions and strike pay are left out (`TRCS:40223-40226`) (D-1h-11).
    Disability per person is also returned for the EIC (`TRCS:40261-40262`).

| # | IRS rule (source) | What the app does | Result |

| 4 | "Although designated Roth contributions are subject to this limit, don't include the excess attributable to such contributions on line 1h" (`i1040gi_ty2025.pdf p. 24`; `iw2w3--2025.pdf p. 20`: the limit is "for elective deferrals and designated Roth contributions") | AA, BB, EE are not read at all (`TRCS:128-130`). ## 9. Limits and out of scope

- **Which part of an excess is Roth** is not asked; the app assumes Roth deferrals never create a line-1h excess.
- **Excess deferrals not distributed** (taxed again on later distribution) — the later-year inclusion is not tracked.
- **The deferral limit is trusted to be 2025's**: plan-specific higher limits are self-declared yes/no answers, not
  amounts.
- **Line 1h is never negative**; losses are not modelled (D-1h-8).
- The earlier knowledge file (`knowledge/line-1h-other-earned-income.md`) said the rules were "verified against
  i1040gi_2025.txt"; that file was Pub. 17 (2024) until 2026-10-24, so that verification is void. This file was checked
  against `i1040gi_ty2025.pdf`.
