# Form 1040 line 1i — how the app does it

IRS rules: `C:\us-tax\new_lines\1i.md`. Flowchart: `C:\us-tax\new_flowcharts\1i.md`.
Paths are relative to `C:\us-tax`. `TRCS` = `us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`.

---

## 1. Status

Line 1i is computed. Each person (taxpayer; spouse unless married filing separately) answers one Yes / No question on
the Combat pay form; a Yes puts that person's whole W-2 box 12 code Q total on line 1i (0 if they have none), a No or
no answer puts nothing. The amount is kept out of line 1z, total income and AGI, and is added to EIC earned income.
Schedule 8812 line 18b and IRA compensation read code Q directly and ignore the election, as the IRS requires. The
Form 2441 combat-pay election is not offered (already recorded as D-1e-4).

**3 differences from the IRS rules** (D-1i-1 … D-1i-3). The one that changes amounts: on a single, head-of-household
or qualifying-surviving-spouse return, a spouse who is on file (for example a married person filing as head of
household) still has their code Q and election counted on line 1i and their code Q on Schedule 8812 line 18b
(D-1i-1). The other two are a misleading UI text (D-1i-2) and the sales-tax table income needing combat pay typed by
hand (D-1i-3).

## 4. How it is computed

Methods:

- Load: `TRCS:2701-2702` (`combat-pay-taxpayer` / `-spouse` personal forms); call `TRCS:3602`.
- `computeCombatPay` `TRCS:40265-40346`; code set `COMBAT_PAY_CODES = Set.of("Q")` `TRCS:131`.
- Code Q sum: `sumW2Box12ByCodes` `TRCS:41568-41612` (digits-only SSN match on `employeeSSN`; returns null for a
  blank SSN; W-2s without box a never match).
- Output: `buildIncome` `TRCS:18606-18609`; kept out of line 1z `TRCS:18480-18488`.

Steps, mirroring `new_lines/1i.md` section 6:

1. **Code Q per person.** The taxpayer SSN comes from `you.ssn` and the spouse SSN from `spouse.ssn`, both resolved
   from the identification forms (`TRCS:2602-2608`, `resolveSpouseIdentification` `TRCS:18156`). The spouse SSN is
   dropped only on a married-filing-separately return (`TRCS:40290`); on single, head-of-household and
   qualifying-surviving-spouse returns a spouse SSN on file is still used (D-1i-1). Each person's total is the sum of
   box 12 code Q on the W-2s whose box a equals that SSN (`TRCS:40301-40306`). No SSN → null (a missing SSN never
   absorbs other people's code Q). Because the match is by SSN, a dependent's W-2 is **not** counted — the D-1a-1
   root cause does not repeat here.
2. **Figure the EIC both ways.** Done in the browser by the comparison panel (two full computes, EIC + ACTC
   compared, saved answer restored). Compute itself does not choose; it follows the saved answer.
3. **Election.** `electCombatPay` per person (`TRCS:40308-40309`; spouse ignored on MFS). Yes → that person's whole
   code Q total, or 0 if none; No / blank → null (`TRCS:40319-40324`). All-or-nothing, as the IRS requires.
4. **Line 1i** = taxpayer + spouse amounts, `roundMoney` half-up to whole dollars (`TRCS:40335-40336`), stored again
   rounded on `Income.nontaxableCombatPayElection` when not null (`TRCS:18607-18608`).
5. **Not in line 1z.** `totalWagesRaw = sumAmounts(line1a … line1h)` (`TRCS:18487`); line 1i is not an operand of
   line 1z or line 9 (`TRCS:18571`).

## 5. Flags and advisories

None. An election with no code Q is only logged (`TRCS:40326-40333`) and gives line 1i = 0 (the UI does not offer
the question in that case; only a direct API save can produce it).

## 8. Compared with the IRS rules

| # | IRS rule (source) | What the app does | Result |
|---|---|---|---|
| 1 | If you elect, enter **all** of your nontaxable combat pay (W-2 box 12 code Q) on line 1i (`i1040gi_ty2025.pdf p. 25, p. 42, p. 43`) | Whole code Q total per electing person (`TRCS:40319-40324`) | Match |
| 2 | On a joint return each spouse makes their own election (`i1040gi_ty2025.pdf p. 43`) | Separate taxpayer / spouse forms and answers | Match |
| 3 | Only your own combat pay (and your spouse's only on a joint return) | Spouse dropped only on MFS (`TRCS:40290, :40309`; `TRCS:56013-56016` for Schedule 8812). On single / HOH / QSS, a spouse on file (spouse tab shown whenever spouse data exists, `shell.component.ts:1919-1921`; spouse resolved with no status check, `TRCS:2606-2608`) with code Q and Yes adds to line 1i, and their code Q always adds to Schedule 8812 line 18b. EIC and ACTC overstated, no flag. Typical case: a married person living apart who files as head of household and entered the spouse | **Deviation D-1i-1** |
| 4 | Line 1i is not added to line 1z (`Form 1040 (2025)`: "z Add lines 1a through 1h") | Excluded (`TRCS:18487`) | Match |
| 5 | Figure the EIC with and without the election (`i1040gi_ty2025.pdf p. 42`) | Comparison panel computes both and recommends; user decides | Match |
| 6 | EIC earned income = Step 5 line 3 + elected combat pay (`i1040gi_ty2025.pdf p. 42`) | Adds line 1i to EIC earned income (`TRCS:51293-51295`); AGI unchanged | Match (line 27a's own earned-income gaps: D-1z-3) |
| 7 | Schedule 8812 line 18b = all nontaxable combat pay, election or not (`i1040s8.pdf p. 3, p. 8`) | All code Q (`TRCS:56008-56018`, `:56475`) | Match (but D-1i-1) |
| 8 | The election affects the EIC only; the ACTC always counts all combat pay (`i1040s8.pdf p. 3, p. 8`) | UI says the choice counts combat pay "when the IRS calculates two specific credits — the Earned Income Credit and the Additional Child Tax Credit" (`form-combat-pay-taxpayer.component.ts:28, :54, :78`; spouse copy). The answer changes nothing on Schedule 8812; the comparison's ACTC side is the same both ways, so the recommendation is still right | **Deviation D-1i-2** (cosmetic, misleading text) |
| 9 | IRA compensation includes nontaxable combat pay (`i1040gi_ty2025.pdf p. 95, p. 98`; `p590a.pdf p. 7`) | Code Q always added (`TRCS:41146-41147`) | Match |
| 10 | Form 2441 has its own combat-pay elections for the credit and for the exclusion (`i2441.pdf p. 4-5`) | Not offered; code Q never reaches Form 2441 | Not supported — already **D-1e-4** |
| 11 | Schedule A optional sales tax table income includes nontaxable combat pay (`i1040sca_2025.pdf p. 5`) | Code Q is not used; the user must type it into "other nontaxable income" (`OptionalSalesTax.java:158-177`; noted in `history.md` 2026-10-23 "Schedule A: optional sales tax tables derived") | **Not supported D-1i-3** (silent; table amount too low if not typed) |
| 12 | Rounding (`i1040gi_ty2025.pdf p. 23`) | Half-up whole dollars on the sum | Match |
| 13 | A child's combat pay is the child's | SSN match keeps a dependent's code Q off the parent's line 1i | Match |

## 9. Limits and out of scope

- Combat pay is read only from W-2 box 12 code Q; there is no field to type an amount (the IRS says the amount
  "should be shown in box 12 of Form(s) W-2 with code Q", `i1040gi_ty2025.pdf p. 43`).
- `combat_pay_total` is saved from the browser but compute recomputes from the W-2s; it is display memory only.
- The dependent's own return has no Combat pay form (`DependentOwnFormScoper`), and the app gives no EIC on that
  return (`dependent-own-eic-ineligible.spec.ts`).
- The top-of-form "Combat zone" checkbox is a different feature (`servedInCombatZone2025`, `TRCS:4849-4859`).
- An election with no code Q stores 0 (not blank); reachable only through the API.
