# Form 1040 line 1z — how the app does it

IRS rules: `C:\us-tax\new_lines\1z.md`. Flowchart: `C:\us-tax\new_flowcharts\1z.md`.
Paths are relative to `C:\us-tax`. `TRCS` = `us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`.

---

## 1. Status

Line 1z itself is computed correctly from the app's lines 1a–1h: each sub-line is rounded to whole dollars, the
eight are added with their signs (a negative line 1f lowers it), line 1i is left out, and the three-state null / 0 /
amount rule is kept. Any error on line 1z comes from its sub-lines (D-1a-*, D-1b-*, D-1c-*, D-1d-*, D-1e-* and the
line 1f–1h files).

The problem is elsewhere: only line 9, Schedule 8812, the dependent's standard deduction, Form 8615 and Form 8379 read
the real line 1z. The Social Security Benefits Worksheet, the IRA-deduction MAGI, the EIC, Form 2441, IRA
compensation, the §469 rental allowance and the §179 limit each **rebuild their own wage figure** from the W-2 list,
and those copies disagree with line 1z.

**5 differences from the IRS rules** (D-1z-1 … D-1z-5), all in those copies. The most serious: Form 4852 W-2
substitute wages, which are part of line 1a, are missing from every rebuilt copy, so with a Form 4852 the taxable
Social Security, the EIC and Form 2441 are figured on too little income (D-1z-1); and the EIC drops most of line 1h
(D-1z-3). All are silent.

## 2. Where the user enters it

Nothing is entered for line 1z. It is the sum of lines 1a–1h; see `new_knowledge\1a.md` … `1h.md` for their inputs.

## 3. Where it is stored

No input storage. Output only (section 6).

## 4. How it is computed

Method: `buildIncome` `TRCS:18226`.

1. **Sub-lines.** Lines 1a–1h are each rounded half-up to whole dollars: `line1a = roundMoney(wagesRaw)` …
   `line1h = roundMoney(otherEarnedIncome)` (`TRCS:18435-18442`; `roundMoney` `TRCS:42389-42401`, `ROUNDING_MODE =
   WHOLE_DOLLAR` `TRCS:121`).
2. **Add.** `totalWagesRaw = sumAmounts(line1a, line1b, line1c, line1d, line1e, line1f, line1g, line1h)`
   (`TRCS:18487`). `sumAmounts` / `addNonNull` (`TRCS:42432-42451`) skip nulls and keep signs — no floor, so a
   negative line 1f carries through.
3. **Round.** `line1z = roundMoney(totalWagesRaw)` (`TRCS:18488`) — a no-op on whole-dollar inputs. This matches the
   form: the sub-lines are the entered (rounded) line amounts.
4. **Line 1i left out.** `combatPayElection` is not an operand (`TRCS:18480-18486`).
5. **Store (null / 0 / amount).** Not null → `Income.totalWages`. Null (no sub-line at all) and either spouse answered
   Yes to "Did you receive any wages" (`hasEmploymentFlag`, `TRCS:18266-18267`) → 0. Otherwise left null
   (`TRCS:18626-18630`), which leaves the preview cell blank.
6. **Line 9.** `line9 = roundMoney(sumAmounts(line1z, line2b, line3b, line4b, line5b, line6b, line7a, line8))`
   (`TRCS:18571`).

`hasIncomeIndicators` (`TRCS:18383-18419`) is computed but no longer used (the early return it fed was removed,
`TRCS:18420-18433`).

are listed on lines 1a–1h.

## 9. Limits and out of scope

- Line 1z is a three-state value (null / 0 / amount), per `knowledge/canonical-null-zero-semantic.md`.
- `roundMoney` rounds half-up away from zero for negatives (a −$0.50 line 1f becomes −$1). The IRS gives no
  separate rule for negative amounts; not treated as a deviation.
- Whether the EIC double counts a statutory employee's W-2 box 1 (kept in its W-2 sum) and the same income entered on
  a Schedule C was not assessed (EIC / Schedule C files).
