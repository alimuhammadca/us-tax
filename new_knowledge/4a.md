# Form 1040 line 4a — how the app does it

IRS rules: `C:\us-tax\new_lines\4a.md`. Flowchart: `C:\us-tax\new_flowcharts\4a.md`. The shared IRA computation
(inputs, storage, Form 8606, flags) is described in full in `new_knowledge\4b.md`; this file covers what is specific
to the gross amount. Paths are relative to `C:\us-tax`. `TRCS` =
`us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`.

---

## 1. Status

Line 4a is computed. For each person (taxpayer; spouse unless married filing separately) the app adds box 1 of every
Form 1099-R with the IRA/SEP/SIMPLE box checked whose recipient TIN matches that person. The return-level total is
shown on line 4a unless the whole return is "fully taxable": gross = taxable, positive, and no exception of any kind.
Earnings on an excess contribution withdrawn by the due date and Form 4852 IRA substitutes are then added.

**4 differences from the IRS rules** (D-4a-1 … D-4a-4), plus D-4b-7 (code P counted) which also changes line 4a.
The most serious: a 1099-R saved with a **blank recipient TIN** is attributed to the taxpayer, so a dependent's (or, on
MFS, the other spouse's) IRA distribution lands on the filer's lines 4a and 4b (D-4a-1, same root cause as D-1a-1 but
narrower: a filled TIN is matched correctly). The others are disclosure-only (line 4a is not in total income).

## 4. How it is computed

Methods: `computeIraDistributions` `TRCS:20083-20659`, `computeIraForPerson` `TRCS:20906-21318`,
`belongsToPersonByTinAndFallback` `TRCS:36002-36019`, augments `TRCS:46884-46950`, `buildIncome` `TRCS:18453`,
`:18659-18661`.

1. **Collect the IRA 1099-Rs of this return.** Per person: `iraSepSimple == true` (`TRCS:20938`) and TIN attribution
   (`TRCS:20941`). With a TIN: must equal the person's SSN (`TRCS:36008-36014`) — a dependent's 1099-R with the
   dependent's TIN is correctly left out. Without a TIN: taxpayer unless only the spouse answered Yes to "Did you
   receive money from an IRA" (`TRCS:36015-36018`) — D-4a-1. On MFS the spouse SSN is null (`TRCS:20135`), so a
   blank-TIN 1099-R of the other spouse goes to the filer.
2. **Leave out other years' amounts.** Not done: code P and code R entries are added like any other (D-4b-7).
3. **Exceptions.** `hasAnyException` per person = rollover, QCD, HFD, other write-in, Form 8606 trigger, **or any box
   2b "taxable amount not determined"** (`TRCS:21202-21207`).
4. **Blank or filled.** `fullyTaxableOverall` = gross > 0, no exception for either person, taxable > 0 and gross =
   taxable (`TRCS:20586-20592`). If true, line 4a = null; otherwise the rounded gross of both persons (`TRCS:20605`).
   Because a traditional IRA 1099-R normally has box 2b checked (`i1099r--2025.pdf p. 13`), the ordinary fully taxable
   case shows line 4a filled (D-4a-2).
5. **Add gross.** Per person Σ box 1 (`TRCS:20944-20945`), rounded per person (`TRCS:21282`), added (`TRCS:20586`).
6. **Augments.** Returned-excess earnings are added to 4a and 4b (`TRCS:46905-46906`); Form 4852 line 8a is added to 4a
   (`TRCS:46937-46938`). Both use `addNonNull`, so when line 4a was blank (fully taxable 1099-Rs) it becomes **only**
   the added amount (D-4a-3). The Form 4852 amount is added even when the incorrect 1099-R it replaces is still on file
   (D-4a-4).
7. **Output.** `roundMoney` (`TRCS:18453`), set only when not null (`TRCS:18659-18661`). The whole IRA record is null
   (line 4a blank) when nothing meaningful exists (`TRCS:20617-20626`).

## 5. Flags and advisories

Specific to line 4a: none. The IRA flags (upload gate, IRA/SEP/SIMPLE checkbox not determined, QCD age, rollover
one-per-year, Form 8606 guards) are listed in `new_knowledge\4b.md` §5. `IRA_STATEMENT_UPLOAD_REQUIRED` is satisfied by
an IRA 1099-R of **any** person in the account (`TRCS:21502-21503`).

## 8. Compared with the IRS rules

| # | IRS rule (source) | What the app does | Result |
|---|---|---|---|
| 1 | Gross IRA distributions on 4a when an exception applies or part is nontaxable (`i1040gi_ty2025.pdf p. 27`; `p590b.pdf p. 22`) | Σ box 1 of both persons (`TRCS:20586`, `:20605`) | Match |
| 2 | Only you and your spouse on a joint return (`i1040gi_ty2025.pdf p. 27`); a child's IRA is the child's | TIN matched; **blank TIN → taxpayer** (`TRCS:36015-36018`); `owner_role` unused. A dependent's blank-TIN IRA 1099-R (offered on the dependent tab) is added to the parent's 4a and 4b; on MFS the other spouse's blank-TIN 1099-R likewise | **Deviation D-4a-1** (same root cause as D-1a-1: household-wide statement list, person told apart only by TIN) |
| 3 | Fully taxable → 4a blank (`i1040gi_ty2025.pdf p. 27`) | Box 2b checked counts as an exception, so a fully taxable traditional IRA distribution with 2b checked shows 4a filled (`TRCS:21202-21207`) | **Deviation D-4a-2** (cosmetic) |
| 4 | A returned 2025 contribution: contribution + earnings on 4a (`i8606.pdf p. 7`); a Form 4852 amount is part of the total | Augments add only the earnings to 4a; when 4a was blank it becomes just the added amount (`TRCS:46905`, `:46937`) | **Deviation D-4a-3** (cosmetic) |
| 5 | Form 4852 replaces a missing or incorrect 1099-R (`f4852.pdf p. 1`) | Added on top of any 1099-R still on file; no payer match or flag | **Deviation D-4a-4** (double count if the wrong 1099-R is kept) |
| 6 | Code P (2024 income) and 2026 recharacterizations not on the 2025 return (`i8606.pdf p. 6–7`) | Code P counted | see **D-4b-7** |
| 7 | IRA vs pension routing by the IRA/SEP/SIMPLE box (`i1040gi_ty2025.pdf p. 26, 28`) | `iraSepSimple` true → line 4; unknown → non-overridable block | Match |
| 8 | MFS: own distributions only | Spouse form and SSN nulled (`TRCS:20113`, `:20135`) | Match (filled TIN) |
| 9 | Round only the total (`i1040gi_ty2025.pdf p. 23`) | Per person, then total | D-4b-11 (≤ $1) |

## 9. Limits and out of scope

- The app does not decide an "exception" per distribution; it decides once per return (IRS: "figure the taxable
  amount of each distribution", `i1040gi_ty2025.pdf p. 27`), which gives the same 4a total.
- Recharacterizations made in 2026 must simply not be entered (no input asks about them).
- Whether a Single / head-of-household return with a stale spouse identification form would attribute a spouse-TIN
  1099-R is **unverified** (only the MFS guard nulls the spouse; the sidebar normally hides the spouse tab).
