# Form 1040 line 6a — how the app does it

IRS rules: `C:\us-tax\new_lines\6a.md`. Flowchart: `C:\us-tax\new_flowcharts\6a.md`.
Paths are relative to `C:\us-tax`. `TRCS` = `us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`.

---

## 1. Status

Line 6a is computed. The app adds SSA-1099 box 5 (`netBenefitsAmount`) and RRB-1099 box 5 (`netSSEBAmount`) of the
taxpayer and — on a joint return — the spouse, choosing each statement by its SSN / recipient number, subtracts any
Supplemental Security Income (SSI) amount typed on the Social Security form, and stores the result. A negative total
(repayments larger than benefits) is shown as 0 and the excess is routed to Schedule A line 16 or a §1341 credit.
Blocking flags cover missing statements, an SSI "Yes" without an amount, and an excess repayment over $3,000 with no
remedy.

**The D-1a-1 root cause does not repeat for an SSA-1099 that has box 2 filled in**: every return (single, joint,
head of household, MFS, dependent's own) keeps only SSA-1099s whose box 2 equals the taxpayer's or (joint) the
spouse's SSN, so a dependent's SSA-1099 stays off the parent's line 6a — matching Pub. 17 "Who is taxed".

**6 differences from the IRS rules** (D-6a-1 … D-6a-6). The most serious: the SSI amount the user types is
subtracted from SSA-1099 box 5, although box 5 never contains SSI, so line 6a and 6b are understated (D-6a-1); and an
RRB-1099 whose recipient number is not exactly the taxpayer's or spouse's SSN (a truncated number, a claim number, a
typo) is dropped with no flag (D-6a-2).

## 4. How it is computed

Methods:

- Orchestrator: `computeSocialSecurityBenefits` `TRCS:33715-34319`, called from `prepare` at `TRCS:4439-4470`.
- Per person: `computeSocialSecurityForPerson` `TRCS:34321-34423`.
- Attribution: `belongsToPersonSsa1099` `TRCS:35895-35912`, `belongsToPersonRrb1099` `TRCS:35914-35931`.
- Excess repayment: `maybeEmitExcessSsaRrbRepaymentFlag` `TRCS:34457-34517` (called `TRCS:5081`); Schedule A line 16
  add-on and the 2024 refigure `TRCS:4874-4886`, `refigurePriorYearSocialSecurity` `TRCS:15419-15437`.
- Output: `buildIncome` `TRCS:18457`, `TRCS:18706-18708`.

Steps, mirroring `new_lines/6a.md` section 6:

1. **Collect the statements that belong on this return.** All SSA-1099 and RRB-1099 rows of the account are loaded
   (`FormSsa1099Mapper.java:70-80`). On MFS the spouse form and the spouse SSN are set to null (`TRCS:33778`,
   `TRCS:33812`). Each row then goes to the taxpayer pass or the spouse pass (`TRCS:33814-33833`):
   - Box 2 / recipient number present: kept only if, after removing non-digits (`normalizeSsn` `TRCS:53713`), it
     **equals** the taxpayer's SSN (taxpayer pass) or the spouse's SSN (spouse pass) (`TRCS:35901-35907`,
     `TRCS:35920-35926`). Anything else — a dependent's SSN (correct), a truncated number, a railroad claim number, a
     typo — is dropped. For an SSA-1099 a number that is nobody's in the household raises
     `STATEMENT_DOES_NOT_BELONG_TO_FAMILY` (blocking; `TRCS:13850-13925`); RRB-1099 is deliberately not in that check
     (`us-tax-be/.../microservices/StatementSsnRules.java:32-35,111`), so a mismatched RRB-1099 vanishes silently
     (D-6a-2).
   - Box 2 blank: the row goes to the taxpayer unless only the spouse answered "had benefits"
     (`TRCS:35908-35911`, `TRCS:35927-35930`) — on any filing status, including a dependent's statement (D-6a-3).
   - Dependent's own return: `you.ssn` is the dependent's (`multireturn/DependentOwnFormScoper.java:155-166`), so the
     dependent's SSA-1099 counts there.
2. **Take box 5.** Only `netBenefitsAmount` (SSA-1099) and `netSSEBAmount` (RRB-1099) are read
   (`TRCS:34350`, `TRCS:34376`). A row with box 3 / box 4 but a blank box 5 adds nothing (D-6a-4).
3. **SSI.** If the person answered Yes to SSI, the typed SSI amount is subtracted from that person's box 5 total,
   floored at 0 (`TRCS:34399-34401`) (D-6a-1). No input exists for SSDI paid for terrorist-attack injuries (D-6a-6).
4. **Add.** Each person's total is rounded (`TRCS:34422`), then the two are added and rounded again
   (`TRCS:33856`) (D-6a-5). Negative box 5 amounts offset positive ones, including across spouses — matching
   Pub. 17.
5. **Negative total.** If the sum is negative, the absolute value is kept as `excessSsaRrbRepayment`, and line 6a is
   set to **0** (`TRCS:33880-33887`); line 6b becomes 0 (`TRCS:34863-34865`). After line 12 is known:
   excess ≤ $3,000 → advisory `SOCIAL_SECURITY_EXCESS_REPAYMENT_NO_IN_RETURN_REMEDY`; excess > $3,000 → added to
   Schedule A line 16 (only the part included in 2024 income when the 2024 figures are typed, `TRCS:4878-4885`) unless
   a §1341 credit is entered (Schedule 3 line 13b); standard deduction and no §1341 → blocking
   `SOCIAL_SECURITY_EXCESS_REPAYMENT_REQUIRES_MANUAL_HANDLING` (`TRCS:34457-34517`).
6. **Output.** If neither person has an amount and nobody answered "had benefits", the whole record is null
   (`TRCS:33857-33859`, `TRCS:34288-34295`); otherwise line 6a is stored (0 when the concept applies but sums to 0).

## 8. Compared with the IRS rules

| # | IRS rule (source) | What the app does | Result |
|---|---|---|---|
| 1 | Line 6a = total of box 5 of all SSA-1099 and RRB-1099 (`i1040gi_ty2025.pdf p. 32`, worksheet line 1) | Sums `netBenefitsAmount` and `netSSEBAmount` of kept rows (`TRCS:34346-34377`) | Match |
| 2 | Joint return: both spouses' benefits (`p17.pdf p. 64`) | Taxpayer pass + spouse pass (`TRCS:33814-33856`) | Match |
| 3 | "Who is taxed": the person with the legal right to the benefits; a child's are the child's (`p17.pdf p. 65`) | SSA-1099 kept only when box 2 equals the taxpayer's / spouse's SSN on every return type (`TRCS:35901-35907`); a dependent's SSA-1099 with box 2 stays off the parent's return and counts on the dependent's own return. **The D-1a-1 root cause does not repeat here.** | Match |
| 4 | SSI is not a social security benefit and is never on the SSA-1099 ("They don't include Supplemental Security Income (SSI) payments", `p17.pdf p. 64`); line 6a is the box 5 total | Subtracts the typed SSI amount from the person's box 5 total (`TRCS:34399-34401`); the unit test pins 17,300 instead of 18,000; a Yes without an amount blocks. Example: box 5 $18,000 and $6,000 SSI typed → line 6a $12,000, and line 6b figured on $12,000 | **Deviation D-6a-1** (silent understatement of 6a / 6b) |
| 5 | RRB-1099 benefits belong to the recipient (`p17.pdf p. 64–65`) | Kept only when `recipientIdNumber` digits exactly equal the taxpayer's / spouse's SSN (`TRCS:35920-35926`); the form's help allows SSN/ITIN/EIN and the field is free text; RRB-1099 is excluded from the household-SSN check (`StatementSsnRules.java:32-35`). A truncated identifier, a claim number or a typo drops the whole RRB-1099 with no flag | **Deviation D-6a-2** (silently omitted income) |
| 6 | Same "who is taxed" rule when box 2 is blank | Blank box 2 / recipient number → taxpayer pass (or spouse pass if only the spouse said "had benefits") on every filing status (`TRCS:35908-35911`): a dependent's statement saved without box 2 lands on the parent's line 6a. Box 2 is marked required in the UI; whether a save without it is refused was not verified. Same family as D-1a-1 / D-2b-2 (household statements told apart only by TIN) | **Deviation D-6a-3** (low) |
| 7 | Box 5 is box 3 minus box 4 (`p17.pdf p. 65`) | Reads box 5 only (`TRCS:34350`, `:34376`); a statement typed with boxes 3 and 4 but box 5 left blank contributes nothing, with no flag (the UI's repayment check does fall back to box 3 − box 4, `form-social-security-benefits-taxpayer.component.ts:867-868`, but the backend does not) | **Deviation D-6a-4** (silent omission) |
| 8 | Negative box 5 offsets positive ones, also between spouses (`p17.pdf p. 68`) | Signed amounts summed before the zero clamp (`TRCS:33856-33887`) | Match |
| 9 | Repayments > benefits: none taxable, no worksheet; excess over $3,000 → Schedule A line 16 or §1341 credit (Schedule 3 line 13b, `i1040gi_ty2025.pdf p. 117`); $3,000 or less not deductible (`p17.pdf p. 68`) | Line 6a = 0, 6b = 0; Schedule A line 16 auto-add / §1341 credit / blocking flag / advisory (`TRCS:34457-34517`, `:4874-4886`) | Match (the value printed on line 6a for a negative total is not stated by the IRS sources; 0 is the app's choice) |
| 10 | Rounding: add with cents, round only the total (`i1040gi_ty2025.pdf p. 23`) | Each person's total is rounded (`TRCS:34422`), then the sum is rounded (`TRCS:33856`). Taxpayer $1,000.50 + spouse $1,000.50 → $2,002 instead of $2,001 | **Deviation D-6a-5** (low, ±$1) |
| 11 | SSDI paid for terrorist-attack injuries is not income even if the SSA-1099 shows it (`i1040gi_ty2025.pdf p. 31`) | No question or adjustment; the full box 5 is used. The user could only lower box 5 by hand, against the statement | **Not supported D-6a-6** (silent overstatement, rare) |
| 12 | Non-SSEB tier 1 / tier 2 railroad benefits are pensions (`p17.pdf p. 64`) | Only RRB-1099 box 5 (SSEB) here; RRB-1099-R feeds lines 5a/5b | Match |
| 13 | MFS: only your own benefits | Spouse form and spouse SSN nulled on MFS (`TRCS:33778`, `:33812`) | Match |

## 9. Limits and out of scope

- **Forms SSA-1042S / RRB-1042S** (nonresident aliens) and foreign social security are not in the catalog.
- **Lump-sum death benefit** has no field; it is not on the SSA-1099 box 5 in the first place.
- The **lump-sum amounts by year** on the SSA-1099 description / RRB-1099 boxes 7–9 are stored but not used; the
  election rows are typed separately (see `6c.md`).
- **Child's benefits paid in the parent's name** with the parent's SSN on box 2 cannot be split; the IRS case where
  the statement is in the child's name works (row 3).
