# Form 1040 line 6c — how the app does it

IRS rules: `C:\us-tax\new_lines\6c.md`. Flowchart: `C:\us-tax\new_flowcharts\6c.md`.
Paths are relative to `C:\us-tax`. `TRCS` = `us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`.

---

## 1. Status

Line 6c is computed. When the taxpayer's Social Security form says the benefits include a back payment for earlier
years, the app figures a second taxable amount — the 2025 part of the benefits with 2025 income, plus, for each
earlier year typed as a row, that year's refigured taxable benefits less what was already reported — and, when the
taxpayer elected the method **and** the result is lower than the normal worksheet, checks line 6c and uses it on
line 6b. Four blocking flags force the prior-year details; an advisory explains a dropped election. The Pub. 915
worksheets themselves are not in `docs\books`, so the formula could not be checked line by line (it was checked
against the app's QA scenario sc_00237).

**3 differences from the IRS rules** (D-6c-1 … D-6c-3): the spouse's back-payment rows on a joint return are ignored
(D-6c-1); a prior year picked as "Married filing jointly" in the form gets the $25,000 base instead of $32,000
(D-6c-2); and through the UI the election is blocked unless the earlier year was married filing separately, because
a question shown only for that status is required for every row (D-6c-3).

## 4. How it is computed

Methods: orchestrator `TRCS:34097-34238`; `computeTaxableSocialSecurityLumpSum` `TRCS:35011-35113`; validators
`validateLumpSumPriorYearReportedAmounts` `TRCS:34529-34560`, `validateLumpSumPriorYearOverridesPresent`
`TRCS:34595-34672`; re-run inside the Pub. 590-A coordination `TRCS:4638-4658`.

1. **Gate.** Only the taxpayer form is read (`TRCS:34097-34098`, `:35023`). On an MFS spouse leg the spouse form has
   already been renamed to the taxpayer form, so it works there; on a joint return the spouse form's rows are never
   read (D-6c-1).
2. **Normal figure** = the regular worksheet on all of line 6a (`TRCS:34087-34095`, `6b.md`).
3. **Election figure** (only if "back payment" = Yes, `TRCS:34114-34117`):
   - total allocated = Σ `lumpSumAllocatedToPriorYear` (`TRCS:35029-35035`); none → the normal figure;
   - 2025 part = line 6a − total allocated, run through the worksheet with this year's inputs and this year's MFS
     path (`TRCS:35039-35051`);
   - for each row: benefits = previously reported + allocated; worksheet with the row's other income, tax-exempt
     interest, exclusions (line 5) and adjustments, under the row's filing status (`normalizeFilingStatus`, which
     does not recognise the dropdown values `MarriedFilingJointly` / `MarriedFilingSeparately` and returns them
     unchanged, `TRCS:53666-53693`) or the current one, and the row's "lived with spouse" answer
     (`TRCS:35055-35100`); additional = max(0, refigured − previously reported taxable) (`TRCS:35106-35109`);
   - election figure = 2025 part + Σ additional (`TRCS:35112`).
4. **Choose.** Line 6c = true and line 6b = election figure only if elected **and** election < normal
   (`TRCS:34180-34186`). Elected but not lower → line 6c false, normal figure, advisory (`TRCS:34197-34220`).
5. **Clamp.** Line 6b ≤ 85% of line 6a and ≥ 0 (`TRCS:34276-34279`).
6. **Pub. 590-A.** When the IRA deduction is cut, the election is re-run with the new worksheet line 7 and the same
   "lower only" test (`TRCS:4638-4667`).

## 8. Compared with the IRS rules

| # | IRS rule (source) | What the app does | Result |
|---|---|---|---|
| 1 | Check line 6c if you elect the method (`i1040gi_ty2025.pdf p. 31`); elect "if it lowers your taxable benefits" (`p17.pdf p. 66`) | Checked only when elected and lower (`TRCS:34180-34186`); advisory otherwise | Match |
| 2 | Earlier-year amounts are figured with that year's income; no amended return (`p17.pdf p. 66`) | Per-row refigure with typed prior-year figures (`TRCS:35055-35110`) | Match in shape; worksheet lines **unverified** (Pub. 915 not available) |
| 3 | The election applies to the benefits on the joint return (both spouses' back payments) | Only the taxpayer form's rows are read (`TRCS:34097-34098`, `:35023`); the spouse form offers the same question and rows (`form-social-security-benefits-spouse.component.ts:170-190,258`), which are ignored on a joint return with no flag. (The taxpayer form's rows have a "Benefit owner" picker, so the spouse's rows can be typed there.) | **Deviation D-6c-1** (election silently unavailable for the spouse's back payment) |
| 4 | An earlier joint year uses that year's joint base amount ($32,000 / $44,000 in the worksheet; `i1040gi_ty2025.pdf p. 32`) | The dropdown saves `MarriedFilingJointly`; `normalizeFilingStatus` keeps it unchanged and the worksheet tests `"Married filing jointly".equalsIgnoreCase(...)` (`TRCS:34896`), so the earlier year gets $25,000 / $34,000. Example: earlier-year joint income $28,000, $6,000 allocated, no earlier benefits → $3,000 + $28,000 = $31,000 → $3,000 taxable under the $25,000 base instead of $0 under the joint $32,000 base | **Deviation D-6c-2** (election figure overstated; election weaker or dropped) |
| 5 | The election is open to any filer with a back payment (`p17.pdf p. 66`) | `SOCIAL_SECURITY_LUMP_SUM_PRIOR_YEAR_DEFAULTS_APPLIED` (non-overrideable) requires `priorYearMfsLivedWithSpouseAnyTime` on every row (`TRCS:34612`), but the UI shows that question only when the row's status is MFS (`form-social-security-benefits-taxpayer.component.ts:490`) and new rows start with it null (`:739`); the filing-status help even says "Leave blank" though blank also blocks. Through the UI, an election for a Single / joint / HOH earlier year cannot be completed (found by reading the template and validator; not run in a browser) | **Deviation D-6c-3** (blocked; the user must drop the election) |
| 6 | Lump-sum death benefit is not this election (`p17.pdf p. 66`) | No field for it | Match |
| 7 | Line 6b with the election still never above 85% of benefits | Clamp `TRCS:34276-34279` | Match |

## 9. Limits and out of scope

- The prior-year figures are typed by hand; SSA-1099 box 3 descriptions and RRB-1099 boxes 7–9 (stored) are not used
  to prefill the rows. The `owner` of a row is not used in the arithmetic.
- `hasLumpSumAllocationByYear` is stored and shown but not read by compute.
- Pub. 915 Worksheets 2–4 are not in `docs\books`; the recompute shape is the app's reading of them.
