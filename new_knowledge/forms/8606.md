# Form 8606 — how the app does it

IRS rules: `C:\us-tax\new_lines\forms\8606.md`. Flowchart: `C:\us-tax\new_flowcharts\forms\8606.md`. The line 4a / 4b /
4c side of the same computation (triggers, QCDs, rollovers, code handling, line 4b override) is in
`C:\us-tax\new_knowledge\4b.md` — its deviations are referenced here by id, not re-derived. Paths are relative to
`C:\us-tax`. `TRCS` = `us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`; `IRA form` =
`us-tax-ui/src/app/forms/form-ira-income-taxpayer.component.ts` (the spouse copy `form-ira-income-spouse.component.ts`
has the same Form 8606 fields).

---

## 1. Status

Form 8606 is built per person (taxpayer and, unless married filing separately, spouse) by `buildForm8606`
(`TRCS:21344-21450`) whenever one of the five line-4b "Exception 2" triggers fires (basis question, conversion
question, a Roth distribution that is not all code Q, returned contribution / recharacterization, any code J or T
1099-R — `TRCS:21043-21047`). All three parts are computed line by line in IRS order: line 7 is derived from the
person's non-Roth IRA Forms 1099-R box 1 less the excluded kinds; the line 10 ratio is capped at 1.000; line 14 is the
basis left; Part II uses line 8 / line 11; Part III works from typed line 19 / 22 / 24 with the $10,000 cap on line
20. Lines 15c + 18 + 25c replace the person's line 4b figure. Two blocking flags guard the inputs (line 4 > line 1;
year-end value blank). On the spouse's own MFS return the spouse's IRA form is moved into the filer slot, so each
separate return gets its own Form 8606.

What is missing is mostly at the edges of the form and across years: **basis is never carried from one year to the
next** — line 2, 22 and 24 are typed every year and the app's own prior-year line 14 is not used (D-8606-2); a Form 8606
for **nondeductible contributions with no distribution cannot be reached from the UI**, and line 1 is not linked to
the IRA-deduction phase-out (D-8606-1); one Form 8606 per decedent for inherited IRAs, the Worksheet 1-1 special
computation, the Line 15c / 25c Worksheets and the required explanatory statements are not modelled.

**10 differences from the IRS rules** (D-8606-1 … D-8606-10), plus the line-level ones already recorded for line 4b
(D-4b-1, -2, -4, -5, -6, -7, -8, -10) that show on this form.

## 4. How it is computed

Methods: orchestrator `computeIraDistributions` (`TRCS:20083-20659`, called at `TRCS:3746`); per person
`computeIraForPerson` (`TRCS:20906-21318`); the form `buildForm8606` (`TRCS:21344-21450`); guards
`form8606ProrataYearEndValueMissing` (`TRCS:21326-21338`) and the line 4 / line 1 check (`TRCS:21213-21214`,
`:21301-21306`, flags `:20496-20529`); header `TRCS:5218-5225`; Roth recapture for Form 5329 `rothConversionRecapture`
(`TRCS:21461-`).

Steps, mirroring `new_lines\forms\8606.md` section 6:

1. **Whose form.** `computeIraForPerson` runs for "taxpayer" and "spouse". On MFS the spouse's IRA form and SSN are
   nulled (`TRCS:20113`, `:20135`), so only the filer's form can exist; on the spouse's own MFS return
   `us-tax-be/.../multireturn/MfsFormScoper.java` moves every `-spouse` personal form into the `-taxpayer` slot, so the
   spouse's Form 8606 is built there as the filer's. Match.
2. **When a form is built.** `hasException2` (`TRCS:21043-21047`) — basis question Yes, conversion question Yes, Roth
   question Yes unless every Roth-coded 1099-R is code Q, returned-contribution question Yes, or any code J / T 1099-R.
   Nothing else builds a Form 8606, and none of these is reachable unless "Did you receive money from an IRA this
   year?" is Yes; answering Yes without an IRA 1099-R on file blocks with `IRA_STATEMENT_UPLOAD_REQUIRED`
   (`TRCS:21494-21514`). So a person whose only 2025 IRA event is a nondeductible contribution cannot get the form
   through the UI (D-8606-1). Compute itself would build it — `Hrb2025Sc00054Test` seeds the IRA form directly with
   `hadIraDistributions` absent and gets line 14 — the gap is the UI gate. Conversely the basis question alone (old
   basis, nothing in 2025) builds a form the IRS does not require (D-8606-6).
3. **Line 1** = `nondeductibleContributionsCurrentYear` as typed (`TRCS:21349`). It is not derived from the IRA
   Deduction Worksheet: when the engine reduces the claimed Schedule 1 line 20 deduction by the MAGI phase-out
   (`TRCS:4600-4690`), the cut is not moved to line 1 and the advisory
   `SOCIAL_SECURITY_IRA_COORDINATION_DEDUCTION_REDUCED_BY_PHASEOUT` does not mention Form 8606 (D-8606-1).
4. **Line 2** = `basisPrevFromPriorYear8606Line14` as typed (`TRCS:21350`). No prior-year bridge exists: the app's 14
   carryforward bridges (`importedPriorYear*`) do not include Form 8606, and `out_form_8606.part1_line14...` is never
   read back for the next year (D-8606-2).
5. **Lines 3–5**: line 3 = 1 + 2 (`addNonNull`), line 4 typed, line 5 = 3 − 4 floored at 0 (`TRCS:21351-21353`).
   Blocking `FORM_8606_LINE4_EXCEEDS_LINE1_*` when line 4 > line 1. Match.
6. **"No distribution or conversion" branch.** Not tested as such: the code always goes on. With no distribution and
   no conversion, line 7 and 8 are null, line 9 = line 6 alone, line 10 is computed if line 6 > 0, lines 11–13 stay
   null and line 14 = line 3 (`TRCS:21370-21390`). Line 14 is right; lines 6, 9 and 10 are filled although the form
   says "Do not complete the rest of Part I" (D-8606-6, cosmetic).
7. **Line 6** = `valueAllTraditionalSepSimpleIrasAtYearEnd` as typed (`TRCS:21354`). Blank with basis and a
   distribution or conversion → non-overridable blocking `FORM_8606_MISSING_YEAR_END_IRA_VALUE_*`
   (`TRCS:20538-20557`, `NonOverrideableFlags.java:193-199`); an explicit 0 is accepted. No question or help asks for
   outstanding rollovers or the 2025-repayment reduction (help `IRA form:1516`) (D-8606-4).
8. **Line 7** (`TRCS:21359-21369`) = Σ box 1 of the person's IRA 1099-Rs whose codes are not J / Q / T
   (`grossTraditionalIra`, `TRCS:20963-20970`) − max(typed rollover, code G box 1) − **typed** QCD (D-4b-2) − HFD −
   line 8 − returned contribution / recharacterization − inherited distributions (D-4b-1), each step floored at 0.
   No code filter: code P / 8 / N / R entries are in it unless the user types them as returned (D-4b-7, D-4b-8). No
   Worksheet 1-1 special computation when a 2025 contribution may not be fully deductible (D-8606-5).
9. **Line 8** = `totalTraditionalIraConvertedToRothFor8606Line8` as typed (`TRCS:21355`); the converted amount must
   also be in a 1099-R's box 1, since line 7 subtracts it.
10. **Line 9** = 6 + 7 + 8 (`sumAmounts`, null only if all three are null).
11. **Line 10** (`TRCS:21372-21386`): computed only when line 5 ≠ 0 and line 9 > 0; `line5 ÷ line9` to 10 decimals,
    capped at 1. The arithmetic uses the 10-decimal ratio (IRS: "at least 3 places" — a convention choice, Match). It
    is stored for printing as a whole part and a "decimal part" = the fraction × 1,000,000 rounded
    (`TRCS:21384-21385`), which the preview prints with thousands separators and without leading zeros (D-8606-7).
12. **Lines 11–14**: line 11 = 8 × 10, line 12 = 7 × 10, line 13 = 11 + 12, line 14 = 3 − 13 floored at 0
    (`TRCS:21387-21390`). Match. The Line 15c Worksheet line 6 add-back is not modelled (D-4b-6).
13. **Lines 15a–15c**: 15a = 7 − 12; 15b = the typed "disaster repayments" amount, not the qualified-disaster share
    (`TRCS:21392`, D-4b-5); 15c = 15a − 15b floored at 0 (`TRCS:21391-21393`). No Line 15c Worksheet (D-4b-6).
14. **Part II**: line 16 = line 8, line 17 = line 11, line 18 = 16 − 17 floored at 0 (`TRCS:21395-21397`). With no
    basis line 10 is null, so line 11 and 17 are null and line 18 = line 16 — the IRS result. Match.
15. **Part III** (`TRCS:21399-21415`): line 19 typed (not taken from the code J / T 1099-Rs — D-4b-4); line 20 typed,
    capped at $10,000 and floored at 0 (the reduction for earlier first-home distributions is the user's); 21 = 19 −
    20; 22 typed; 23 = 21 − 22; 24 typed; 25a = 23 − 24; 25b typed "disaster repayments" (D-4b-5); 25c = 25a − 25b; all
    floored at 0. Lines 22 and 24 have no worksheet, and the line 22 help (`IRA form:1522`) asks for every Roth
    contribution ever made without subtracting earlier Roth distributions (D-8606-3).
16. **Rounding and storage**: each line is rounded to whole dollars when stored (`TRCS:21417-21448`); the person's
    line 4b uses the rounded 15c + 18 + 25c (`TRCS:21144`).
17. **Header**: the taxpayer's Form 8606 gets the return header — on a joint return "Filer & Spouse" with the filer's
    SSN (`TRCS:5220`, `:52571-52590`); the spouse's form gets the spouse's own name and SSN (`TRCS:5223-5224`,
    `:52593-52606`) (D-8606-8).
18. **Not produced at all**: a second Form 8606 for an inherited IRA with basis (one form per person; D-8606-9, same
    root as D-4b-1); the statements for recharacterizations, returned contributions and divorce transfers
    (D-8606-10); a stand-alone Form 8606 (the app always files with a return — out of scope).

### Worked example from `new_lines` traced through the code

Pat Example: 1099-R code 7 box 1 10,000 and code 2 box 1 33,000 (IRA box checked); IRA form: basis Yes, conversion Yes,
line 2 6,000, line 1 7,000, line 6 87,000, line 8 33,000. `grossTraditionalIra` 43,000 → line 7 = 43,000 − 33,000 =
10,000; line 9 130,000; ratio 0.1; lines 11 3,300, 12 1,000, 14 8,700, 15c 9,000, 18 29,700; line 4b 38,700 — the IRS
result. Pat must type 8,700 as line 2 again next year (D-8606-2).

## 9. Limits and out of scope

- Filing Form 8606 by itself (no income tax return) — the app only prepares returns; self-filing scope.
- The Line 15c / 25c Worksheets, Form 8915-F and the Pub. 590-B Worksheet 1-1 special computation are not modelled
  (D-4b-6, D-8606-5).
- Lines 2, 22 and 24 are the user's numbers every year; the app keeps its own Form 8606 in `out_form_8606` but has no
  next-year import (D-8606-2).
- Deliberate: null (not 0) lines when a part does not apply — Part III is all null when line 19 is blank.
