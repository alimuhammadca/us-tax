# Form 1099-CAP (`1099-cap`) — every box and where it goes

Paths are relative to `C:\us-tax`. `TRCS` = `us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`.
`MAP` = `us-tax-be/src/main/java/com/ustax/microservices/statement/Form1099CapMapper.java`. `UI` =
`us-tax-ui/src/app/forms/form-1099-cap.component.ts`.

---

## 1. What this statement is

Form 1099-CAP, Changes in Corporate Control and Capital Structure (**Rev. April 2025**, `docs/IRS-Forms/f1099cap.pdf`
p. 2, Copy B), is sent by a corporation that underwent a change in control or a substantial change in capital structure
to a shareholder who received cash, stock or other property for its stock. "You have received this statement because
the corporation has reasonably determined that you may be required to recognize gain … Report any gain from the exchange
on Form 8949. However, you cannot claim a (loss) on Form 8949 as a result of this exchange. See chapter 4 of Pub. 550"
(`f1099cap.pdf` p. 3, Instructions for Shareholder). Copy B box 5 note: "You cannot claim a loss based on the amount in
box 2." Filer instructions: `i1099cap.pdf` p. 3 (boxes 1-4). Pub. 550 is not in `docs\books\`.

So the 2025 return use is: the gain, if any, as a sale on **Form 8949** (and Schedule D); amount realized = box 2; basis
from the shareholder's records; no loss.

**Whose statement it is.** "SHAREHOLDER'S TIN", `shareholderTIN` (`MAP:109`), seeded with the person tab's SSN on a new
entry (`us-tax-ui/src/app/service/statement-entry-state.service.ts:28-34`). Family check `StatementSsnRules.java:79`.

**Person filter (the D-1a-1 question).** Box 2 is never put on any return (no income path). The only compute use is a
cross-check (`crossCheckSpecialtyCapitalStatements`, `TRCS:11129-11233`, called `TRCS:3373`) that compares box 1's date
with the Form 8949 rows typed on the taxpayer's and spouse's Capital gain/loss forms; it reads every 1099-CAP of the
household without a TIN test (`TRCS:11138`, loop `TRCS:11175-11189`). So a spouse's (on MFS) or dependent's 1099-CAP can
trigger the check on another person's return (part of **D-1099-cap-1**).

**Storage.** Entity `Se1099Cap` / table `se_1099_cap` (`MAP:97-125`). UI `syncPdfToForm` `UI:236-266`: box 2 through
`parseAmountAndNotes` (no negative box; D-ui-1 not relevant); box 3 through `Number()` (**D-1099-cap-2**). Upload
extraction: `GenericFieldMapper.java:708`.

## 3. Checkboxes and codes

VOID and CORRECTED only — stored. Box 4 may hold "C" / "P" / "O" class abbreviations (`i1099cap.pdf p. 3`); stored.

## 4. Questions the app asks with this statement

None on the screen. The user must enter the exchange as a Form 8949 row on the Capital gain/loss form; the app only
checks that row for a loss.

## 5. Differences from the IRS instructions

New:

**D-1099-cap-1 — the "no loss" block matches by date only, across the whole household.**
IRS: "you cannot claim a (loss) on Form 8949 as a result of this exchange" (`f1099cap.pdf p. 3`) — the bar is on the
loss **from this exchange**, by the shareholder who received the form.
Code: any Form 8949 row on either Capital gain/loss form whose date sold equals box 1, and whose proceeds are below its
basis, blocks the return (`TRCS:11177-11186`) — whatever security the row is, and whoever the 1099-CAP belongs to (no TIN
test; statements are household-wide; on MFS the other spouse's 1099-CAP counts). A legitimate loss on unrelated stock
sold the same day is stopped. Conversely, a loss row for the exchange typed with a slightly different date passes.
Effect: **BLOCKING** false positive (overrideable — the code is not in `NonOverrideableFlags`), or a silent miss.
Severity **low-medium**.

**D-1099-cap-2 — box 3 typed with a thousands comma is lost.**
`syncPdfToForm` stores box 3 as `Number(r['box3'])` (`UI:262`): "1,000" gives `NaN`, sent as null. Effect: **cosmetic**
(box 3 is never read). Severity **low**.
