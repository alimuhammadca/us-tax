# Form 1099-QA — Distributions From ABLE Accounts

Statement form id `1099-qa`. Paths are relative to `C:\us-tax`. `TRCS` =
`us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`. Line-level analysis already done in

## 1. What this statement is

The program that maintains an ABLE (Achieving a Better Life Experience, IRC §529A) account sends Form 1099-QA for
distributions from the account. Copy B is the recipient's copy. Form revision used: **Form 1099-QA (Rev. April 2025)**
(`docs/IRS-Forms/f1099qa.pdf` p. 2, title).

IRS instructions used:

- Recipient: "Instructions for Recipient" — `f1099qa.pdf` p. 3: box 2 "Generally, amounts distributed that are used to
  pay for qualified disability expenses, or rolled over to another ABLE account within 60 days, are not included in
  income. Report taxable amounts as 'Other income' on Form 1040 or 1040-SR. Also see Form 5329."
- Filer: `i1099qa--2025.pdf` p. 3 (boxes 1-6).
- Where it goes: Schedule 1 line 8q, "Distributions from this type of account may be taxable if (a) they are more than
  the designated beneficiary's qualified disability expenses, and (b) they were not included in a qualified rollover.
  See Pub. 907" (`i1040gi_ty2025.pdf` p. 92); the 10% additional tax on Form 5329 Part II → Schedule 2 line 8
  (`i5329.pdf` p. 5-6; `i1040gi_ty2025.pdf` p. 112). Also Form 8880 line 4 (distributions from "ABLE accounts" reduce
  the saver's credit contributions, `f8880.pdf` p. 1-2). Pub. 907 itself is not in `docs\books\`.

**Whose statement it is.** "RECIPIENT'S TIN", stored as `recipientTIN`, pre-filled with the person-tab SSN on a new entry
(`us-tax-ui/src/app/service/statement-entry-state.service.ts:28-34`). A TIN of nobody in the household raises the
blocking `STATEMENT_DOES_NOT_BELONG_TO_FAMILY` (`us-tax-be/.../microservices/StatementSsnRules.java:69`).

**Storage.** Mapper `us-tax-be/src/main/java/com/ustax/microservices/statement/Form1099QaMapper.java` (save keys
`:96-123`, list `:70`); entity `Se1099Qa` / table `se_1099_qa`. UI `us-tax-ui/src/app/forms/form-1099-qa.component.ts`,
`syncPdfToForm` `:196-226`: boxes 1-6, payer / recipient blocks, CORRECTED and **VOID** go into the model; the mapper has
no `void` column (D-1099-qa-3). Upload extraction: `GenericFieldMapper.java:717-722, 769-771` (`postProcess1099Qa`).

**How it is computed.** `computeAbleTaxableEarnings` (`TRCS:8439-8476`), called at `TRCS:4303-4305`:

1. Runs only if "ABLE account: qualified disability expenses paid this year" (`ableQualifiedDisabilityExpenses`) is
   filled on the taxpayer's and/or (not MFS) the spouse's Other incomes form; else null and the typed line 8q stands
   (`TRCS:8445-8450`).
2. Sums box 1 and box 2 of every 1099-QA whose TIN is the taxpayer's, the spouse's (not MFS) **or blank**, skipping box 4
   program-to-program transfers (`TRCS:8455-8466`).
3. Expenses ≥ box 1 total → 0; else taxable = earnings − expenses × earnings ÷ box 1 (`TRCS:8467-8475`).
4. Line 8q = the computed amount, or the typed `otherIncomeAbleDistributions8q` when nothing was computed
   (`preferComputedExclusion`, `TRCS:32488-32491`).
5. Form 5329 Part II line 5 = line 8q (+ QTP), line 6 = typed `form5329Line6ExceptionAmount`, line 8 = 10%
   (`TRCS:5401-5422`) → Schedule 2 line 8.
6. Form 8880 line 4: box 1 of the person's 1099-QAs (TIN must match; box 4 transfers left out) is added to the
   distributions (`sum1099QaDistributions`, `TRCS:57854-57865`; used `:57973`, `:57983`).

**Person filter (the D-1a-1 question).** Positive for a filled TIN — a dependent's ABLE 1099-QA (TIN = the child) is
not counted on the parent's return. A **blank** TIN is counted on every return of the household (D-1099-qa-1). Form 8880
uses a strict match (blank TIN not counted).

## 5. Differences from the IRS instructions

Reused: **D-8-11** — with a 1099-QA on file and the expenses question blank, line 8q is empty and no flag is raised
(`new_knowledge\8.md` row 23).

New:

**D-1099-qa-1 — a 1099-QA with a blank TIN is counted on every return of the household.**
IRS: ABLE distributions are the designated beneficiary's income (`i1040gi_ty2025.pdf` p. 92, "the designated
beneficiary's qualified disability expenses").
Code: `boolean mine = tin == null || …` (`TRCS:8458-8460`) — a TIN-less 1099-QA joins the ratio on the taxpayer's
return, on both MFS legs (each leg's own `you`), and on a dependent's own return; the household TIN check skips blank TINs
(`TRCS:13900-13904`). Form 8880 uses a strict match, so the same statement is treated two ways.
Effect: **silent wrong amount** (the earnings taxed on more than one return, or on the wrong person's) — but only when
the expenses question is answered on that return (D-8-11 gate). Severity: **low**.

**D-1099-qa-2 — one ratio for both spouses' ABLE accounts, and 60-day ABLE rollovers are not asked.**
IRS: the test is the designated beneficiary's distributions against that beneficiary's qualified disability expenses
(`i1040gi_ty2025.pdf` p. 92); box 1 "includes amounts distributed that the designated beneficiary intends to roll over to
another ABLE account", which are not income if rolled over within 60 days (`f1099qa.pdf` p. 3; ABLE rollover defined in
`i5329.pdf` p. 2).
Code: on a joint return both spouses' 1099-QAs and both spouses' expenses are pooled into one ratio (`TRCS:8445-8447`,
`:8455-8466`); only box 4 program-to-program transfers are excluded (`TRCS:8463`) — there is no rollover question.
Effect: **silent wrong amount** — an ABLE-to-ABLE 60-day rollover is partly taxed; two beneficiaries' figures blend.
Severity: **low** (both spouses each holding an ABLE account, or a 60-day rollover, is rare).

**D-1099-qa-3 — the VOID checkbox shown on the screen is not stored.** The UI renders VOID and copies it to
`model.void` (`form-1099-qa.component.ts:29`, `:199`); `Form1099QaMapper` has no `void` column. VOID is a Copy A item
(`i1099gi--2025.pdf` p. 11). Effect: **cosmetic**. Severity: **low**.
