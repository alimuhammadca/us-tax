Paths are relative to `C:\us-tax`. `TRCS` = `us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`.
`MAP` = `us-tax-be/src/main/java/com/ustax/microservices/statement/Form1099RMapper.java`. `UI-R` =

## 1. What this statement is

Form 1099-R, Distributions From Pensions, Annuities, Retirement or Profit-Sharing Plans, IRAs, Insurance Contracts,
etc. (2025 — `docs/IRS-Forms/f1099r.pdf`), is sent by a plan, IRA trustee or insurer to each person who received a
distribution of $10 or more. Copy B is filed with the return when box 4 shows withholding (`f1099r.pdf p. 4`).

IRS instructions used:

- Recipient: "Instructions for Recipient" on the back of the copies — `f1099r.pdf p. 5` (general, account number,
  boxes 1, 2a), `p. 7` (boxes 2b-6, box 7 codes 1-D), `p. 9` (codes E-Y, boxes 8-19).
- Filer: `i1099r--2025.pdf` (Instructions for Forms 1099-R and 5498, 2025) — box 1 `p. 10`, box 2a `p. 11-13`, box 2b /
  box 3 `p. 13`, box 4 `p. 14`, boxes 5 / 6 `p. 15`, box 7 `p. 15`, boxes 8 / 9a / 9b `p. 16`, boxes 10-19 `p. 17`,
  Table 1 "Guide to Distribution Codes" `p. 18-20`.
- Where each box goes: `i1040gi_ty2025.pdf p. 26-28` (lines 4a-4c), `p. 28-31` (lines 5a-5c, rollovers, lump sums),
  `p. 39` (line 25b); `i5329.pdf p. 3` (Form 5329 line 1); `i8606.pdf`; `f4972.pdf`; `i8960.pdf p. 7-8` (Form 8960
  line 3); `f8880.pdf p. 2` (Form 8880 line 4); `i1040sca_2025.pdf p. 3` (Schedule A line 5a).

**Whose statement it is.** "RECIPIENT'S TIN", saved as `recipientTIN` (`MAP:125`). A new 1099-R created on a person tab
is pre-filled with that person's SSN (`us-tax-ui/src/app/service/statement-entry-state.service.ts:28-34`). A filled TIN
that matches nobody in the household raises the blocking `STATEMENT_DOES_NOT_BELONG_TO_FAMILY` (`TRCS:13891-13913`,
rule `StatementSsnRules.java:59`). The mapper lists every 1099-R of the account for the year — the whole household
(`MAP:81-90`).

**Person filter (the D-1a-1 question).** The income paths filter by TIN on **every** filing status
(`belongsToPersonByTinAndFallback`, `TRCS:36002-36019`): a dependent's 1099-R carrying the child's SSN never reaches the
parent's lines 4a-5b. The D-1a-1 root cause survives in three places:

- a 1099-R saved **without** a recipient TIN goes to the taxpayer of whatever return is computed (D-4a-1, D-5a-1);
- line 1h reads the whole list (code 3 / 8 entries) with only an MFS spouse skip (D-1h-13);
- box 4 withholding (line 25b) and boxes 14 / 17 (Schedule A line 5a) are filtered only on MFS and dependent's-own
  returns — a dependent's 1099-R withholding is credited on the parent's single / joint / HOH return while its income
  is not (same mechanism as **D-1099-int-1**, which this extends to 1099-R box 4; and **D-1099-int-3**, which already
  names 1099-R).

On MFS with community property, non-IRA 1099-Rs are split before any reader (box 1, box 4;
`CommunityProperty.split1099R`, `us-tax-be/.../CommunityProperty.java:563-571`, called `TRCS:3110-3111`); IRAs are not
split.

**Storage.** Entity `Se1099R` / table `se_1099_r`; up to two state / local rows in `Se1099RStateLocalInfo` /
`se_1099_r_state_local_info` (`MAP:165-190`). `owner_role` is stored but no compute path reads it.

**UI.** The screen is a replica of the form; inputs bind `pdfRaw['boxN']` and `syncPdfToForm` (`UI-R:278-327`) copies
every box into the saved model (`UI-R:205-231`). Every replica box has a mapper column and every mapper key is on the
screen — no typed value is lost. Two small gaps: box 8's notes are not kept (`UI-R:309`, no notes column), and VOID has
no input on the replica (the saved value is only carried through, `UI-R:237`, `:281`). The IRA/SEP/SIMPLE checkbox
defaults to unchecked (`UI-R:220`). Upload extraction (Azure `prebuilt-tax.us.1099R`) writes the same keys
(`us-tax-be/src/main/resources/field-mappings.json`, `Box7` → `distributionCodes`; post-processing
`us-tax-be/.../GenericFieldMapper.java:5023-5055`); box 7 is stored as the raw string.

## 3. Checkboxes and codes

### Box 2b and the IRA/SEP/SIMPLE box

- **2b "Taxable amount not determined"** — see box 2b above. For a traditional IRA the IRS tells the payer to put box 1
  in box 2a **and** check this box (`i1099r--2025.pdf p. 13`), so it is the normal state of a traditional-IRA 1099-R,
  not a warning. The app treats it as a line 4c "exception" (D-4a-2) and drops the entry from the early-distribution
  base (D-1099-r-2).
- **2b "Total distribution"** — not read.
- **IRA/SEP/SIMPLE** — drives lines 4 vs 5. A Roth IRA and a recharacterization are printed **unchecked**
  (`i1099r--2025.pdf p. 15`, `p. 7`), so they go to lines 5a / 5b (D-1099-r-1).

### Box 7 codes

enters at most two codes (`i1099r--2025.pdf p. 15`). All code tests use `parseDistributionCodes` (`TRCS:42068-42081`),
which splits on any non-alphanumeric character: "7, D" or "7 D" gives {7, D}, but "7D", "1B", "4G" or "81" is a
single token that matches no code (**D-1099-r-9**).

## 4. Questions the app asks with this statement

- **IRA income** (`ira-income-taxpayer` / `-spouse`): rollover amount, QCD (and inherited QCD), HFD, nondeductible
  basis, Roth distributions, conversion, returned contribution / recharacterization, Form 8606 lines, Form 5329 opt-in
  and exception, prior year-end balance for the RMD — see `new_knowledge\4a.md`, `4b.md`, `4c.md`, `forms\8606.md`.
- **Pension / annuity income** (`pension-annuity-income-taxpayer` / `-spouse`): rollover (hint counts code G entries),
  PSO election, Simplified Method / General Rule inputs (cost = box 9b retyped), NUA election, per-annuity streams,
  RMD shortfall, Form 5329 — see `new_knowledge\5a.md`, `5b.md`, `5c.md`.
- **Other earned income**: for each code-3 1099-R, owner and "below the plan's minimum retirement age" (routes to line
  1h); code-8 entries listed — see `new_knowledge\1h.md`.
- **Lump-sum distribution** (Form 4972): picks one 1099-R (`selectedStatementId`) and asks eligibility, box 8 and box
  9a — see `new_knowledge\forms\4972.md`.
- **W-2 Substitute** (Form 4852) line 8 entries replace a missing 1099-R (D-4a-4, D-5a-2 when the incorrect 1099-R
  is kept).

## 5. Differences from the IRS instructions

Reused (already analysed): D-4a-1 … D-4a-4, D-4b-1 … D-4b-12 (D-4b-1 coordinator-verified), D-4c-1 / D-4c-2,
D-5a-1 … D-5a-5, D-5b-1 … D-5b-14 (D-5b-1 coordinator-verified), D-5c-1 / D-5c-2, D-1h-5 / -6 / -7 / -13, D-4972-1 …
D-4972-9, D-8606-1 … D-8606-10, D-1099-int-1 (extended to 1099-R box 4), D-1099-int-3. The Form 5329 work of
2026-10-24 (`PensionEarlyDistributionBase`, `IraPriorExcessAbsorbed`, `history.md`) is reflected in the box 1 / 2a
rows and is not repeated.

New:

**D-1099-r-1 — a Roth IRA (codes J / Q / T) or recharacterization (codes N / R) 1099-R entered as printed lands on
lines 5a / 5b.**
IRS: "Do not check the box for a distribution from a Roth IRA that is not a Roth SIMPLE IRA or for an IRA
recharacterization" (`i1099r--2025.pdf p. 15`; also `p. 7`: recharacterization "It is not necessary to check the
IRA/SEP/SIMPLE checkbox"). Roth IRA distributions and recharacterizations are IRA distributions reported on lines 4a /
4b (`i1040gi_ty2025.pdf p. 26-27`: "an IRA includes … Roth IRA"; Exception 2 items 2 and 6).
Code: the IRA path keeps only `iraSepSimple == true` (`TRCS:20938`); everything else goes to the pension path
(`TRCS:21980`), which does not look at J / Q / T / N / R. The Roth logic of the IRA path (`TRCS:20963-20978`, Form 8606
Part III, the code-Q shortcut) is reached only if the user checks the box **against** the form; the null-checkbox
blocker tells the user to "set the IRA/SEP/SIMPLE checkbox to match the source form" (`TRCS:23229-23231`).
Effect (traced, not run): a code-Q Roth distribution of $10,000 with box 2a blank and no other pension 1099-R → line 5a
$10,000 and line 5b $10,000 (box 1 fallback, `TRCS:22148`) instead of line 4a $10,000 / line 4b $0; a code-J
distribution is fully taxed instead of going through Form 8606 Part III; with another pension 1099-R that has box 2a,
the Roth box 1 is on line 5a and adds $0 to 5b (D-5b-1). If the person has no checked IRA 1099-R and answered the IRA
question Yes, `IRA_STATEMENT_UPLOAD_REQUIRED` (blocking, overridable, `TRCS:21506-21510`) fires without naming the
cause. **Silent wrong amount** (overstatement for Q / T / J-basis) when another IRA 1099-R is on file. Severity **high**.

**D-1099-r-2 — an early traditional / SIMPLE IRA distribution (code 1 or S) whose box 2b is checked gets no §72(t)
additional tax.**
IRS: the payer reports a traditional IRA distribution with box 2a = box 1 and "Check the 'Taxable amount not
determined' box in box 2b" (`i1099r--2025.pdf p. 13`); Form 5329 line 1 is "the amount of early distributions
includible in income" (`i5329.pdf p. 3`).
Code: the IRA early base is accumulated only `if (!TRUE.equals(taxableAmountNotDetermined))` (`TRCS:20985-20994`); no
other path adds it, so `iraEarlyDistributionAdditionalTax` stays null and `FORM5329_REQUIRED_FOR_EARLY_DISTRIBUTION`
(which needs a positive amount, `TRCS:21832-21836`) does not fire. The unit test of this feature uses a 1099-R with box
2b unchecked (`TaxReturnComputeServiceTest.java:6100-6125`). The line-4b ceiling added on 2026-09-15 (`TRCS:21230-21280`)
already prevents over-taxing a rolled-over amount, so the guard is no longer needed for that purpose.
Effect: age-45 filer, traditional IRA code 1, box 1 = box 2a = $20,000, box 2b checked, no basis → IRS Form 5329 line 4
$2,000; app $0, no flag. **Silent understatement.** Severity **high**.

**D-1099-r-3 — Form 8880 line 4 counts every 1099-R except codes G and H.**
IRS: line 4 distributions exclude rollovers and trustee-to-trustee transfers, conversions to a Roth IRA, loans treated as
distributions, excess contributions / deferrals and their income, contributions returned by the due date, §404(k) ESOP
dividends, military retirement, and inherited IRAs of a nonspouse beneficiary (`f8880.pdf p. 2`).
Code: `sum1099RDistributions` adds box 1 of every 1099-R of the person except codes G / H (`TRCS:58149-58175`,
`ROLLOVER_DISTRIBUTION_CODES` `TRCS:144`), used for line 4 at `TRCS:57969` and `:57982`. Codes L, 8, P, U, 4 (inherited),
6 / W (not plan distributions at all), N / R, IRA conversions and 60-day rollovers all reduce line 5.
Effect: **silent understatement** of the saver's credit (a $5,000 loan offset or a conversion can wipe out a $2,000
contribution). Severity **medium**.

**D-1099-r-4 — code D annuity income is not carried to Form 8960 line 3.**
IRS: "If code 'D' is shown in box 7 of Form 1099-R, include on Form 8960, line 3, the taxable amount reported in box 2a"
(`i8960.pdf p. 7-8`).
Code: line 3 is only the typed `form8960Line3AnnuitiesOverride` (`TRCS:43473`, `:43514`, `:43597`); code D is never
tested. Effect: **silent understatement** of NIIT for filers above the threshold unless they type the override. Severity
**medium**.

**D-1099-r-5 — a charitable gift annuity's capital gain (code F, box 3) is taxed as ordinary pension income.**
IRS: "For a charitable gift annuity, report as a long-term capital gain as explained in the Instructions for Form 8949"
(`f1099r.pdf p. 7`); the filer puts it in box 3 with code F (`i1099r--2025.pdf p. 13`).
Code: box 3 is read only by Form 4972 (`TRCS:13410-13412`); the pension path puts all of box 2a on line 5b. Effect:
**silent** — total income is right, but the gain misses the capital-gain rates. Severity **low**.

**D-1099-r-6 — §1035 exchanges (code 6) and long-term care charges (code W) are shown on line 5a.**
IRS: "You need not report these amounts on your tax return" (`f1099r.pdf p. 5`).
Code: the pension path adds box 1 to `gross1099R` for every non-IRA entry (`TRCS:22014`); box 2a is 0, so line 5a is
printed with the exchanged value. **Cosmetic** (line 5a is not in total income); the same entries also reduce Form 8880
(D-1099-r-3). Severity **low**.

**D-1099-r-7 — box 10 (amount allocable to an in-plan Roth rollover within 5 years) is never read.**
IRS: "If an amount is reported in this box, see the Instructions for Form 5329" (`f1099r.pdf p. 9`); the recapture
amount of an early designated Roth distribution belongs on Form 5329 line 1 (`i5329.pdf p. 3`).
Code: no reader of `amountAllocableToIRRWithin5YearsAmount`. **Not supported**, silent understatement of the 10% tax.
Severity **low** (rare).

**D-1099-r-8 — a prohibited transaction (code 5) gets no early-distribution tax.**
IRS: prohibited transactions involving an IRA "are considered to be distributions and are generally subject to the
additional tax on early distributions" (`i5329.pdf p. 3`).
Code: only codes 1, S and J build a §72(t) base (`TRCS:20985-20994`, `:22048-22058`, `:21160-21190`). **Not
supported**, silent for an owner under 59½. Severity **low** (rare).

**D-1099-r-9 — two box 7 codes typed together ("1B", "7D", "4G", "81") are not recognised.**
IRS: "enter a numeric and an alpha code" when both apply, at most two (`i1099r--2025.pdf p. 15`).
Code: `parseDistributionCodes` splits on non-alphanumeric characters only (`TRCS:42068-42081`; the same in
`us-tax-ui/src/app/forms/form-other-earned-income.component.ts:1002-1007`); the box 7 input has no format hint
(`UI-R:64`) and extraction stores the raw string (`GenericFieldMapper.java:5023-5031`). "1B", "1L", "1M" lose the 10%
tax; "81" (excess deferral, early) is not routed to line 1h and stays on lines 5a / 5b; "1P" is taxed in 2025; "4G"
counts toward the RMD and Form 8880. **Silent**, depending on how the user types the box. Severity **medium**
(unverified how often users omit the separator).
