# Form RRB-1099 — Payments by the Railroad Retirement Board

Statement form id `rrb-1099`. Paths are relative to `C:\us-tax`. `TRCS` =
`us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`. Line-level analysis already done in
`new_knowledge\6a.md`, `6b.md`, `6c.md`, `6d.md`; their deviation ids are reused here rather than re-derived. The
SSA-1099 counterpart is `new_mappings\ssa-1099.md`.

---

## 1. What this statement is

The Railroad Retirement Board sends Form RRB-1099 to each person paid the **social security equivalent benefit
(SSEB) portion of tier 1** railroad retirement benefits. "Equivalent tier 1 railroad retirement benefits are the part
of tier 1 benefits that a railroad employee or beneficiary would have been entitled to receive under the social
security system. They are commonly called the social security equivalent benefit (SSEB) portion of tier 1 benefits"
(`p17.pdf` p. 64). These are taxed exactly like social security (lines 6a / 6b). The other railroad amounts — the
**NSSEB** portion of tier 1, tier 2, vested dual benefits and supplemental annuities — are on the separate
**Form RRB-1099-R** and are pensions (Form 1040 lines 5a / 5b; `p17.pdf` p. 64: "This chapter doesn't cover … Non-social
security equivalent benefit (NSSEB) portion of tier 1 benefits … see Pub. 575"). The app keeps the two apart: this
statement feeds only line 6a; RRB-1099-R (`rrb-1099-r`) feeds the pension lines.

It is **not an IRS form** and the sources hold **no copy of it**: `docs/IRS-Forms/1099rrb.pdf` is in fact a 2016
**RRB-1099-R** sample (boxes 3 "Employee Contributions" … 12 "Medicare Premium Total"), and `public/irs/` has no
RRB-1099 image. Box captions below are therefore the app's replica captions
(`us-tax-ui/src/app/forms/form-rrb-1099.component.ts:280-328`), confirmed against the IRS text only for the boxes the
IRS names: box 3 gross, box 4 repaid, box 5 net (`p17.pdf` p. 65; `i1040gi_ty2025.pdf` p. 31) and box 10 withholding
(`i1040gi_ty2025.pdf` p. 39). Boxes 1, 2, 6-9 and 11 are **unverified** against a printed 2025 RRB-1099. Pub. 915
(which has the RRB-1099 box explanations) is not in `docs\books\`.

**Whose statement it is.** The recipient in box 2 ("Recipient's Identifying Number"), stored as `recipientIdNumber`.

**Storage.** Mapper `us-tax-be/src/main/java/com/ustax/microservices/statement/FormRrb1099Mapper.java`; entity
`SeRrb1099` / table `se_rrb_1099` (`us-tax-be/src/main/java/com/ustax/entity/SeRrb1099.java:12`). One row per
statement, no child rows. The list call returns every RRB-1099 of the account (`uid`) for the year — the whole
household (`FormRrb1099Mapper.java:71-80`).

**UI.** `us-tax-ui/src/app/forms/form-rrb-1099.component.ts`. The PDF-replica view binds `pdfRaw[...]`
(`:262-328`); Save runs `syncPdfToForm` (`:598-616`) and saves the model (`onVerify`, `:618-629`) with no validation;
load runs `syncFormToPdf` (`:578-596`, wired to `entryLoaded` at `:44`). All 11 boxes plus CORRECTED / DUPLICATE /
tax year reach a mapper key, and every mapper key is on the screen. **No box is lost.** The replica has no payer or
recipient name / address fields; whether the 2025 RRB-1099 prints them could not be checked (no form copy) — they
would not be used in the computation anyway.

**Upload extraction.** `field-mappings.json:1309` (`prebuilt-document` key-value names) and a position grid read off
the replica's own labels — `"^Box 3 - Gross SSEB"`, `"^Box 11 - Medicare Premium Total"` …
(`us-tax-be/src/main/java/com/ustax/microservices/GenericFieldMapper.java:641-645`, `:2279-2314`); the claim number
is tidied by `normaliseRrbClaimNumber` (`:1363`). Whether these anchors match a real RRB-1099's printed captions is
unverified (no copy).

**Person filter (the D-1a-1 question).** For the **income** (box 5) the D-1a-1 root cause does not repeat: on every
filing status a statement with box 2 filled in is kept only if box 2, digits only, equals the taxpayer's or (joint)
the spouse's SSN (`belongsToPersonRrb1099`, `TRCS:35914-35931`). But RRB-1099 is deliberately left out of the
household-SSN check (`us-tax-be/src/main/java/com/ustax/microservices/StatementSsnRules.java:32-35`, skip list
`:110-111`), so any other number (a claim number, a truncated or mistyped SSN) drops the statement silently (D-6a-2). A
blank box 2 is counted as the taxpayer's on every return (D-6a-3). **Box 10** withholding has no person filter on
single / joint / head-of-household / QSS returns (**D-rrb-1099-1**).

## 4. Questions the app asks with this statement

The same Social Security benefits form as SSA-1099 (`social-security-benefits-taxpayer` / `-spouse`;
`new_knowledge\6a.md` §2): "Did you receive Social Security or Railroad Retirement benefits…"
(`hadSocialSecurityBenefits` — gating and the blank-box-2 tie-break), "Did you receive Form RRB-1099?" / "Did you
upload…" (`receivedRrb1099`, `uploadedRrb1099` → blocking `MISSING_UPLOADED_RRB_1099`), the confirm-all-uploaded
answer, SSI (D-6a-1), the earlier-year repayment figures, and the lump-sum election rows (`new_knowledge\6c.md`). The
RRB-1099's own box 5 is counted whether or not `hadSocialSecurityBenefits` is Yes (`TRCS:34372-34377`).

New:

**D-rrb-1099-1 — box 10 withholding is credited even when the statement's benefits are not on this return** (same
root as D-ssa-1099-1 and D-1099-int-1).
IRS: box 10 goes on line 25b (`i1040gi_ty2025.pdf` p. 39) — with the benefits, which belong to "the person who has the
legal right to receive the benefits" (`p17.pdf` p. 65).
Code: line 25b sums `federalIncomeTaxWithheldAmount` of every RRB-1099 in the account (`TRCS:49795-49806`);
`filterWithholdingEntriesForScopedFiler` returns the list unchanged on single / joint / head-of-household / QSS
returns (`TRCS:51808-51813`). Box 5 of the same statement is dropped by `belongsToPersonRrb1099` when box 2 is not
exactly a filer's SSN (`TRCS:35920-35926`). Two cases:
(a) a dependent's RRB-1099 (box 2 = child's SSN) — benefits correctly left off the parent's line 6a, withholding
added to the parent's line 25b (and claimed again on the child's own return);
(b) the filer's **own** RRB-1099 whose box 2 is typed as a claim number or with a digit wrong (D-6a-2) — the benefits
vanish from line 6a while the withholding stays on line 25b, so the return looks complete. On MFS / dependent's-own
returns the positive filter (`TRCS:51818`) drops both, and a blank box 2 drops the withholding but keeps the benefits
(D-6a-3).
Effect: **silent wrong amount** (refund overstated; in case (b) it compounds D-6a-2's understated income).
Severity: **low-medium**.

**D-rrb-1099-2 — a negative box 5 typed with a minus sign, or any negative box 5 re-saved, is stored as positive.**
Same mechanism as D-ssa-1099-2: Save always re-parses the replica (`form-rrb-1099.component.ts:618-619`) with
`parseAmountAndNotes` (`:609`), whose pattern accepts `(1,000.00)` but not `-1000.00`
(`us-tax-ui/src/app/utils/amount-notes-parser.ts:18`), while load writes stored negatives back as `-1000.00`
(`form-rrb-1099.component.ts:589`; `amount-notes-parser.ts:54-55`). IRS: a negative box 5 means none taxable and
offsets other forms (`p17.pdf` p. 68). The backend then adds +1,000 to line 6a (`TRCS:34376`) and the
excess-repayment remedy never runs. The app's own help says box 5 "may be negative (shown in parentheses)"
(`form-rrb-1099.component.ts:525`). Effect: **silent wrong amount** (line 6a / 6b overstated). Severity: **medium**
(rare, large).
