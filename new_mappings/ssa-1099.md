# Form SSA-1099 — Social Security Benefit Statement

Statement form id `ssa-1099`. Paths are relative to `C:\us-tax`. `TRCS` =
`us-tax-be/src/main/java/com/ustax/microservices/TaxReturnComputeService.java`. Line-level analysis already done in
`new_knowledge\6a.md`, `6b.md`, `6c.md`, `6d.md`; their deviation ids (D-6a-1 … D-6a-6, D-6b-1 … D-6b-4,
D-6c-1 … D-6c-3, D-6d-1) are reused here rather than re-derived.

## 1. What this statement is

The Social Security Administration sends Form SSA-1099 to each person who received (or repaid) social security
benefits during the year. It is **not an IRS form**: there are no IRS filer or recipient instructions for it. "If you
received these benefits during 2025, you should have received a Form SSA-1099, Social Security Benefit Statement …
These forms show the amounts received and repaid, and taxes withheld for the year. You may receive more than one of
these forms for the same year. You should add the amounts shown on all the Forms SSA-1099 and Forms RRB-1099"
(`p17.pdf` p. 64).

Sources used:

- Form copy: `us-tax-ui/public/irs/fssa1099_page_01.png` and its field map `fssa1099_field_map_semantic.csv` (also
  `docs/IRS-Forms/1099ssa.pdf`, an image-only PDF of the same page). This is the SSA's **2019 draft** layout
  ("Form SSA-1099-SM (6-2019)", "Draft as of June 21, 2019") — the only copy in the sources. Box captions below are
  from it; the box numbering (1–8 and the two description blocks) has not changed, but a 2025 copy was not available
  to confirm the wording.
- Where each box goes: `i1040gi_ty2025.pdf` p. 31 (lines 6a/6b), p. 32 (Social Security Benefits Worksheet line 1),
  p. 39 (line 25b), p. 95 (Schedule 1 line 17 — Medicare premiums); `p17.pdf` p. 56 (workers' compensation offset),
  p. 64-68 (chapter 7); `i1040sca_2025.pdf` p. 1 (Schedule A line 1 — Medicare Part B / Part D premiums);
  `i7206.pdf` p. 1 (Medicare premiums in the self-employed health insurance deduction). Pub. 915 is **not** in
  `docs\books\`; points that only Pub. 915 settles are marked "unverified".

**Whose statement it is.** The beneficiary in box 2 ("Beneficiary's Social Security Number"), stored as
`beneficiarySSN`. "Benefits are included in the taxable income … of the person who has the legal right to receive the
benefits" (`p17.pdf` p. 65).

**Storage.** Mapper `us-tax-be/src/main/java/com/ustax/microservices/statement/FormSsa1099Mapper.java`; entity
`SeSsa1099` / table `se_ssa_1099` (`us-tax-be/src/main/java/com/ustax/entity/SeSsa1099.java:12`). One row per
statement, no child rows, no VOID / CORRECTED columns. The list call returns every SSA-1099 of the account (`uid`)
for the year — the whole household (`FormSsa1099Mapper.java:70-79`).

**UI.** `us-tax-ui/src/app/forms/form-ssa-1099.component.ts`. Only the PDF-replica view is shown — the form view and
its toggle are hidden by `*ngIf="false"` (`:30-31`). The replica binds `pdfRaw[...]` (`:214-291`); Save calls
`syncPdfToForm` (`:794-821`) and saves the model (`onVerify`, `:824-834`) with no validation. On load the saved model
is copied back into the replica by `syncFormToPdf` (`:772-792`, wired to `entryLoaded` at `:45`). Every replica
field reaches a mapper key; the mapper has no key the screen lacks. **No box is lost** — but see D-ssa-1099-2 for a
value that is changed on the way.

**Upload extraction.** Azure `prebuilt-tax.us.1099SSA` (`us-tax-be/src/main/resources/field-mappings.json:984-1001`:
TaxYear, Beneficiary.SSN / Name / Address, ClaimNumber, Box3-Box6). The two description blocks are read separately
into `benefitsPaidGrossNotes` / `benefitsRepaidNotes` (`us-tax-be/src/main/java/com/ustax/microservices/GenericFieldMapper.java:647-651`,
`:2345-2397`); the address is split into the two address keys (`GenericFieldMapper.java:4262-4296`).

**Person filter (the D-1a-1 question).** For the **income** (box 5) the D-1a-1 root cause does **not** repeat: on
every filing status a statement with box 2 filled in is kept only if box 2 equals the taxpayer's or (joint) the
spouse's SSN (`belongsToPersonSsa1099`, `TRCS:35895-35912`), so a dependent's SSA-1099 stays off the parent's line 6a
(`new_knowledge\6a.md` row 3). A box 2 that is nobody's in the household blocks with
`STATEMENT_DOES_NOT_BELONG_TO_FAMILY` (`us-tax-be/src/main/java/com/ustax/microservices/StatementSsnRules.java:98`).
It **does** repeat for:

- a **blank** box 2 — counted as the taxpayer's on every return of the household (D-6a-3). The visible replica's
  box 2 input carries no `required` (`form-ssa-1099.component.ts:228`) and `onVerify` saves without validation, so a
  blank box 2 is saveable (this settles the "not verified" note in D-6a-3);
- **box 6** withholding (line 25b): no person filter on single / joint / head-of-household / QSS returns
  (**D-ssa-1099-1**).

## 3. Checkboxes and codes — and the items printed in the description blocks

The SSA-1099 has no checkboxes or codes. The description blocks carry items that the IRS sends elsewhere:

| Item (description of box 3 / 4) | IRS destination | App |
|---|---|---|
| Medicare Part B premiums deducted from benefits (also Part D / Part C when withheld) | Medical expense, Schedule A line 1: "The supplemental part of Medicare insurance (Medicare Part B)" and "The premiums you pay for Medicare Part D insurance" (`i1040sca_2025.pdf` p. 1). For a self-employed person: "Medicare premiums you voluntarily pay to obtain insurance in your name … can be used to figure the deduction" — Form 7206 / Schedule 1 line 17 (`i1040gi_ty2025.pdf` p. 95; `i7206.pdf` p. 1), the rest to Schedule A | **Not carried.** The amount exists only inside the free-text box 3 description. The user must type it again: the medical total on the Standard deductions form (help text does not mention the SSA-1099, `us-tax-ui/src/app/forms/form-standard-deductions.component.ts:407`), or `medicarePremiums` on the self-employed deductions form (`form-se-deductions.component.ts:92-95`; read `TRCS:29805`, leftover to Schedule A `:29840`; `new_knowledge\forms\7206.md`). No flag reminds the user. Not a deviation from an IRS rule (the IRS does not take the figure from the SSA-1099 either), but an easily missed deduction |
| Benefits for earlier years (lump-sum back payment, by year) | Lump-sum election, line 6c, Pub. 915 worksheets (`p17.pdf` p. 66) | Not read from the statement; the election rows are typed on the Social Security form (`new_knowledge\6c.md`; D-6c-1 … D-6c-3) |
| Workers' compensation offset | Treated as social security benefits — already in box 3 / 5 (`p17.pdf` p. 56) | Counted through box 5. Match |
| Attorney fees paid from benefits | Included in box 3; the fee's deductibility is a Pub. 915 point (Pub. 915 not in sources — unverified) | Counted through box 5; no deduction offered |
| Voluntary federal tax withheld | Box 6 → line 25b | Box 6 is read (see box 6 row) |
| Repayments by year (box 4 description) | Excess repayment remedy (`p17.pdf` p. 68) | Typed on the Social Security form |

SSI is never on an SSA-1099 ("They don't include Supplemental Security Income (SSI) payments", `p17.pdf` p. 64); the
app's SSI subtraction is D-6a-1.

## 4. Questions the app asks with this statement

All on the Social Security benefits form (`social-security-benefits-taxpayer` / `-spouse`), listed in full in
`new_knowledge\6a.md` §2: "Did you receive Social Security or Railroad Retirement benefits…" (`hadSocialSecurityBenefits`
— gating and the blank-box-2 tie-break), received / uploaded SSA-1099 and the confirm-all-uploaded answer (blocking
upload flags), SSI (D-6a-1), "Benefits repaid for an earlier year" (2024 figures for the >$3,000 remedy), the
lump-sum election rows (`new_knowledge\6c.md`), MFS lived-apart (line 6d, `new_knowledge\6d.md`). The statement's own
income is **not** gated by `hadSocialSecurityBenefits` — a saved SSA-1099 is counted even if the answer is No
(`TRCS:34346-34351`), but then the upload flags do not fire.

## 5. Differences from the IRS instructions

Reused (analysed at line level; see the cited file):

| Id | Box | Summary |
|---|---|---|
| D-6a-1 | 5 | Typed SSI amount is subtracted from box 5 although box 5 never contains SSI |
| D-6a-3 | 2 | Blank box 2 → counted as the taxpayer's on every return (a dependent's statement lands on the parent). Saveable: the visible replica does not require box 2 |
| D-6a-4 | 3, 4, 5 | Box 5 blank with boxes 3 / 4 filled → nothing counted, no flag |
| D-6a-5 | 5 | Per-person rounding before the total (±$1) |
| D-6a-6 | 5 | No way to exclude SSDI paid for terrorist-attack injuries |
| D-6b-1 … D-6b-4 | 5 (via 6b) | Worksheet ordering / inputs — see `new_knowledge\6b.md` |
| D-6c-1 … D-6c-3 | box 3 description (back payments) | Lump-sum election gaps — see `new_knowledge\6c.md` |
| D-6d-1 | — | Line 6d box only shown with benefits — see `new_knowledge\6d.md` |

New:

**D-ssa-1099-1 — box 6 withholding of a statement whose benefits are not on this return is credited anyway** (same
root as D-1099-int-1).
IRS: the withholding goes with the benefits — "include the amount withheld in the total on line 25b. This should be
shown in … box 6, of Form SSA-1099" (`i1040gi_ty2025.pdf` p. 39), and the benefits belong to "the person who has the
legal right to receive the benefits … One-half of the part that belongs to your child must be added to your child's
other income" (`p17.pdf` p. 65).
Code: line 25b adds `voluntaryFederalIncomeTaxWithheldAmount` of every SSA-1099 in the account
(`TRCS:49811-49812`); `filterWithholdingEntriesForScopedFiler` returns the list unchanged when neither
`scopedFilerSsn` nor `mfsOtherSpouseSsn` is set (`TRCS:51808-51813`) — single, joint, head-of-household and QSS
returns. The box 5 of the same statement is dropped by `belongsToPersonSsa1099` (`TRCS:35901-35907`).
Example: a parent (single) saves the child's survivor-benefit SSA-1099 (box 2 = child's SSN, box 5 $9,000, box 6
$900). Line 6a correctly leaves out the $9,000, but line 25b includes the $900; if the child files his or her own
return (filtered by the child's SSN), the $900 is claimed twice.
Secondary: on MFS / dependent's-own returns the filter is positive (`TRCS:51818`), so a **blank** box 2 drops the
withholding on every leg while the benefits are counted on every leg (D-6a-3) — inconsistent, no flag.
Effect: **silent wrong amount** (refund overstated). Severity: **low-medium** (voluntary withholding on a child's
benefits is uncommon).

**D-ssa-1099-2 — a negative box 5 typed with a minus sign, or any negative box 5 re-saved, is stored as positive.**
IRS: "your net benefits in box 5 will be a negative figure (a figure in parentheses) and none of your benefits will be
taxable … a negative figure in box 5 of one form is used to offset a positive figure in box 5 of another form"
(`p17.pdf` p. 68).
Code: Save always runs `syncPdfToForm` (`form-ssa-1099.component.ts:824-826`), which reads box 5 with
`parseAmountAndNotes` (`:815`). Its pattern `(\([\$]?[\d,]+(?:\.\d+)?\)|\$?[\d,]+(?:\.\d+)?)` accepts a parenthesised
negative but has no minus sign (`us-tax-ui/src/app/utils/amount-notes-parser.ts:18`): `-1000.00` gives amount
`1000` and notes `-`. On load `syncFormToPdf` writes the stored value with `toFixed(2)`, i.e. as `-1000.00`
(`amount-notes-parser.ts:54-55`, called from `form-ssa-1099.component.ts:788`). So:
(a) typing `-1,000` saves +1,000; (b) typing `(1,000.00)` saves −1,000 correctly, but opening the statement again and
pressing Save turns it into +1,000; (c) an uploaded negative box 5 is shown as `-…` and becomes positive on
"Verify & Save". The backend then adds +1,000 to line 6a (`TRCS:34350`) instead of netting −1,000, and the
excess-repayment logic (line 6a 0, Schedule A line 16 / §1341) never runs. No flag. The e2e negative-box-5 tests seed
by API (`us-tax-be/e2e/tests/line6abcd-social-security-benefits.spec.ts:342,395,442`) and do not cover the screen.
Effect: **silent wrong amount** (line 6a / 6b overstated, repayment remedy lost). Severity: **medium** (negative
box 5 is uncommon, but the error is large when it happens). The same parser is used for RRB-1099 box 5
(D-rrb-1099-2) and other statements' amount boxes; for amounts that are never negative it is harmless.
