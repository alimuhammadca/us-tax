


**★ The IRS EIC table ROUNDS to whole dollars — never truncate it.** `eicTableLookup` floored until 2026-09-21, putting roughly **half** of all credits $1 below the published table (FLOOR disagrees with 250 of 541 printed phaseout brackets and all 15 phase-in brackets; HALF_UP disagrees with none). The phaseout rate ends in 8, so the bracket-midpoint product carries a .5 fraction about half the time. ★ **The direction matters — the EIC is refundable, so truncation understated refunds and the error always ran against the filer.** Pins: `Sc00384SqaScenarioTest`, `line27a-earned-income-credit.spec.ts`.

**★ One agreeing data point is not a verified rounding rule.** sc_00383's EIC (1,663.335) floors and rounds to the same value, so it passed and appeared to confirm the engine; sc_00384's (1,343.735) did not. When a rounding question arises, check it against **every** printed bracket you can extract, not the one case in front of you — 541 rows settled this in one command where a second scenario had already been misled by one. **★ Don't pattern-match the last finding onto the next scenario.** sc_00377 and sc_00378 were both doc rounding-direction errors, so sc_00384's 21% dependent-care rate looked like a third — it is correct. Form 2441's printed table opens at **$0–15,000 → .35**, which shifts every band away from the "35% less 1% per $2,000 over $15,000" description; 41,000–43,000 → .21. Read the form each time; a streak of similar findings is exactly when a false one becomes easy.

**★ §152(e) needs no Form 8332 flag in the model.** Form 2441's qualifying-person list and the EIC's qualifying-child list are each maintained **separately** from the household dependent list, so a released child is expressed by not claiming the dependency while still listing the child on those two forms. The four benefits — dependency/CTC to the noncustodial parent, HOH + EIC + dependent-care to the custodial one — divide themselves.
